# Разностные образы QEMU — результат

Дата: 2026-10-31. Ветка: `feature/derived-images`, от актуального `main` с документами
из `claude/differential-images-project-4swe3r`.

Реализованы задачи А–Г, TASK-2 и TASK-3. На настоящий стенд изменения не развёрнуты; до включения
функции нужна приёмка GNS3/QEMU/CephFS ниже. Разделы А–Г фиксируют первоначальную
реализацию; правила мониторинга и выключения гостя уточнены в «TASK-2» и «TASK-3».
TASK-3 отменяет прежний совет ручного poweroff: он снова роняет любую лабу,
включая авторскую. Актуальная стендовая приёмка этого поведения — в конце отчёта.

## А. Агент 1.3.0

- `GET /capabilities` объявляет `images_capture` только при `LAB_IMAGES_DIR` и
  доступном `qemu-img`; бюджет — `LAB_CAPTURE_TIMEOUT` (60–3600 с, default 900).
- `POST /images/capture`: строгая модель, безопасные компоненты имён, UUID проекта,
  поиск ноды в единственном `.gns3` проекта, чтение через directory FD / `O_NOFOLLOW`.
  Проверяются текущие `mp1` всех локальных CT через существующий `conf_sections`.
- Снятие и mount/start используют общую блокировку каталога пользователя. Менеджер
  дополнительно резервирует авторский workspace между узлами на всё время capture.
- Проверяются формат, отсутствие внешнего data-file, backing, SHA-256 самостоятельной
  базы и размер. Исходный диск не меняется. На копии `-u` используется только для
  замены абсолютного пути того же родителя; пересадка с производного родителя на
  базу выполняется безопасным rebase без `-u`, затем `check` и проверка размера.
- Файл и готовый MD5-sidecar публикуются без перезаписи с правами `0444`.
  `.part` убираются при завершении/ошибке, старые — при старте и перед capture,
  с исключением файлов активной операции. MD5-cache — 32 hex, как в исходнике
  GNS3 Server 2.2.61 (`gns3server/utils/images.py`); формат сверён по wheel пакета.
- Тесты используют исполняемый fake `qemu-img` в PATH, а не подмену маршрута:
  первое/повторное снятие, неверная база/backing, размер, симлинки, busy, отсутствие
  ноды, запрет перезаписи, тайм-аут, очистка и общая блокировка с mount.

## Б. Менеджер 0.14.0

- Миграция `009_derived_images.sql`: каталог производных, долговечные capture,
  авторская идентичность с nullable `instance_id`, `library_lab_id`, `mode` и
  отдельными ограничениями живых сессий. Обычная студенческая семантика сохранена.
- `options.mode: authoring` разрешён только с `lab` и `library_lab_id`, без
  `instance_id`/`lab_ref`. Ключ каталога включает сайт, автора и лабу, отделён от
  студенческого; default/предел длительности — `AUTHORING_MAX_DURATION=240` мин.
- Одинаковый `lab_def` продолжает проект; смена определения создаёт новый UUID.
  Возврат к ранее использованному определению также создаёт новый проект.
- POST capture сохраняет запрос и будущие имена до выполнения, обычный оркестратор
  останавливает лабу/CT и паркует слот. Worker последовательно снимает ноды,
  сохраняет checkpoints, использует бюджет агента с запасом и публикует все записи
  каталога одной транзакцией. GET отдаёт running/done/failed. Запуск того же
  workspace во время capture блокируется; старая stopped-сессия после нового
  запуска не может снять чужое по времени содержимое проекта.
- Checkpoints продолжаются после перезапуска worker. При потерянном ответе после
  создания файла операция безопасно завершается ошибкой без публикации каталога;
  повтор failed-capture использует новые имена. Готовые непривязанные файлы не удаляются.
- Каталог = `IMAGES_FILE` + БД, изолирован по сайту, читается без перезапуска.
  Свойства и разрешения производного наследуются от базы. Retired остаётся
  доступен старым определениям; PATCH меняет только публичные метаданные.
- `supersedes` связывает предыдущее снятие того же автора/лабы/ноды, даже если автор
  перед новым снятием снова выбрал базовый или чужой образ.
- `capture: false` выставлен в примерах для `lab-uplink` и `linux-switch`.
  Feature/options объявляются по capabilities, авторские запуски размещаются
  только на подходящих узлах. Контракты и ответ плагину обновлены.

## Уточнения контракта и долги

1. У снимаемой базы требуется приватное поле `sha256: "sha256:<64 hex>"` в
   `IMAGES_FILE`: хеш вычисляет администратор при установке файла. Без него обычные
   запуски разрешены, снятие отклоняется как `not_capturable`. Менеджер сам CephFS
   не читает и новых прав на хранилище не получает.
2. Добавлен поиск авторского запуска `GET /sessions?user_id=&library_lab_id=` и
   поле `capture_nodes` — кандидаты, доступные и после остановки. TASK-2 заменил
   список имён объектами `{name, status}` на основе истории запусков workspace.
   Список активностей курса авторские запуски не включает.
3. У существующего API агента/слота нет удаления отдельного проекта. Прежний каталог
   при смене `lab_def` остаётся рядом с новым. Долг записан в AGENT_REQUESTS §6;
   новый разрушительный маршрут не вводился.
4. Атомарность относится к каталогу БД. После сбоя или потери ответа могут остаться
   готовые файлы без записи каталога. Автоматической физической очистки, общей квоты
   и seal нет — это оставленные дизайном следующие этапы.
5. Совместимость linked clone над производным образом не доказана локальными тестами.
   На самостоятельный `qemu-img convert` реализация автоматически не переключается.

## TASK-2

Задание из `claude/differential-images-project-4swe3r`, коммит `f9e1e94`,
перенесено в `feature/derived-images` отдельным коммитом. Доработка остаётся
в том же PR #82. Версии: Slot **0.14.0**, Manager **0.15.0**, плагин **0.16.0**;
Agent **1.3.0** сохраняет прежний контракт.

### Что сделано

- **Слот:** fenced async `POST /v1/labs/{project_id}/nodes/{node_id}/shutdown`,
  строгий timeout 30–300 с (default 120), идемпотентная операция. Через QGA-брокер
  отправляется `guest-shutdown` powerdown, затем опрашивается GNS3 до stopped.
  Ошибка не вызывает принудительного выключения и не переводит лабу в FAILED.
  Разные выбранные ноды выключаются параллельно; смена владельца ждёт принятые
  операции. Добавлены capability, контракт, версия и перепечатанный манифест.
- **Менеджер:** новая миграция `010_guest_consistent_capture.sql`, история
  запуска имён в workspace и последний pre-stop статус в сессии. Кандидаты —
  `{name, status}` запускавшихся QEMU-нод без `capture: false`; poweroff не
  удаляет ноду, новая сессия того же проекта сохраняет историю.
  Новое поле force строго boolean; нода без истории отклоняется как never_started.
- **Quiesce:** выбранные работающие гости выключаются параллельно в общем
  бюджете `IMAGE_SHUTDOWN_TIMEOUT`. Идентификаторы операций сохраняются в БД.
  Только после свежего подтверждения stopped выставляется stop_requested;
  далее выполняется прежняя остановка и снятие агентом. Частичный сбой даёт
  GUEST_NOT_STOPPED / retryable с именами и причинами, сессия работает, файлы не
  снимаются. Без capability или маршрута слота — GUEST_SHUTDOWN_UNSUPPORTED.
- **Явное сохранение как есть:** force разрешает продолжить после ошибки;
  только неподтверждённые гости попадают в forced и derived.forced. Из уже
  stopped-сессии нода, работавшая перед остановкой, без force даёт HTTP 409
  guest_not_stopped с советом запустить лабу снова или сохранить как есть.
- **Плагин и mock:** статусы и совет sync/poweroff в окне, причины по нодам,
  «Повторить» / «Сохранить как есть» с явным предупреждением, значок у образа.
  HTTP 409 преобразуется PHP-посредником в строгий типизированный результат
  для этого диалога. Mock имитирует quiesce, частичный сбой, отсутствие поддержки,
  force и настоящий poweroff из своей поддельной консоли. AMD и карты обновлены.
- **Установка:** allowlist и compatibility обновлены, сборщик принимает
  идентичность Slot 0.14.0. Перед обновлением менеджера требуются миграции.

### Уточнения реализации

1. Монитор слота теперь разрешает выключенный QEMU в READY-лабе: иначе poweroff
   вручную или quiesce приводили бы к ошибке всей сессии. Отсутствующие ноды
   и остановка не-QEMU по-прежнему проверяются; поколение снимка защищает
   от запоздавшего результата монитора во время shutdown.
2. QGA по протоколу не присылает успешный ответ на guest-shutdown. Брокер
   отправляет команду и закрывает канал, а успех подтверждает только GNS3.
   Прямых обращений к QGA-сокету в обход брокера нет.
3. Последние статусы сохраняются с временем начала наблюдения: запоздалый ответ
   не может заменить более свежий. Если свежий опрос перед остановкой недоступен,
   статус становится unknown и последующее снятие из stopped требует force.
4. Образы, уже существовавшие до миграции 010, консервативно получают forced:
   прежняя реализация гостей через QGA не выключала. Миграция 009 не менялась.

## TASK-3

Дата: 2026-11-01. Задание `4a9f7aa` перенесено из ветки владельца отдельным
коммитом в `feature/derived-images`; работа продолжается в PR #82.
Версии: Slot **0.14.1**, плагин **0.16.1**, Manager **0.15.0** (рабочий код
менеджера не менялся), Agent **1.3.0**.

### Что сделано

- В записи лабы хранится `shutdown_nodes`: список id нод после SUCCEEDED
  маршрута shutdown. Только остановленный QEMU из этого списка допускается
  в READY, его provisioning пропускается. Любая другая неработающая или
  отсутствующая нода снова даёт `Required node stopped or missing` и FAILED.
  Это правило общее для студента и автора; поля режима в билете не добавлялись.
- Ошибка shutdown список не пополняет. Если после ошибки гость выключился
  позже, монитор переводит лабу в FAILED. Пока операция RUNNING, монитор
  ждёт её результата, как в TASK-2. Изменения списка используют существующую
  проверку generation, поэтому устаревший снимок не перезаписывает результат.
- Список сохраняется после перезапуска Lifecycle и очищается при DEPLOYING
  (deploy/resume), STOPPED и наблюдении повторного started у конкретной ноды.

  остановку и ручной poweroff. После quiesce выбранные ноды записаны в список,

  Тест ручного poweroff проверяет обработку SLOT_LAB_FAILED; тест повтора
  использует восстановившийся QGA вместо ручного выключения.

списка при создании нового Lifecycle и его очистку при продолжении.
