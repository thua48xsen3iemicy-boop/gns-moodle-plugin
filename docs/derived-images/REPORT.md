# Разностные образы QEMU — результат

Дата: 2026-10-31. Ветка: `feature/derived-images`, от актуального `main` с документами
из `claude/differential-images-project-4swe3r`.

Реализованы задачи А–Г. На настоящий стенд изменения не развёрнуты; до включения
функции нужна приёмка GNS3/QEMU/CephFS ниже. Слот, его маршруты и монтирования не менялись.

## А. Агент 1.3.0

- `GET /capabilities` объявляет `images_capture` только при `LAB_IMAGES_DIR` и
  доступном `qemu-img`; бюджет — `LAB_CAPTURE_TIMEOUT` (60–3600 с, default 900).
- `POST /images/capture`: строгая модель, безопасные компоненты имён, UUID проекта,
  поиск ноды в единственном `.gns3` проекта, чтение через directory FD / `O_NOFOLLOW`.
  Проверяются текущие `mp1` всех локальных CT через существующий `conf_sections`.
- Снятие и mount/start используют общую блокировку каталога пользователя. Менеджер
  дополнительно резервирует авторский workspace между узлами на всё время capture.
- Проверяются формат, отсутствие внешнего data-file, backing, SHA-256 самостоятельной
  базы и размер. Исходный диск не меняется. На копии `-u` используется только для
  замены абсолютного пути того же родителя; пересадка с производного родителя на
  базу выполняется безопасным rebase без `-u`, затем `check` и проверка размера.
- Файл и готовый MD5-sidecar публикуются без перезаписи с правами `0444`.
  `.part` убираются при завершении/ошибке, старые — при старте и перед capture,
  с исключением файлов активной операции. MD5-cache — 32 hex, как в исходнике
  GNS3 Server 2.2.61 (`gns3server/utils/images.py`); формат сверён по wheel пакета.
- Тесты используют исполняемый fake `qemu-img` в PATH, а не подмену маршрута:
  первое/повторное снятие, неверная база/backing, размер, симлинки, busy, отсутствие
  ноды, запрет перезаписи, тайм-аут, очистка и общая блокировка с mount.

## Б. Менеджер 0.14.0

- Миграция `009_derived_images.sql`: каталог производных, долговечные capture,
  авторская идентичность с nullable `instance_id`, `library_lab_id`, `mode` и
  отдельными ограничениями живых сессий. Обычная студенческая семантика сохранена.
- `options.mode: authoring` разрешён только с `lab` и `library_lab_id`, без
  `instance_id`/`lab_ref`. Ключ каталога включает сайт, автора и лабу, отделён от
  студенческого; default/предел длительности — `AUTHORING_MAX_DURATION=240` мин.
- Одинаковый `lab_def` продолжает проект; смена определения создаёт новый UUID.
  Возврат к ранее использованному определению также создаёт новый проект.
- POST capture сохраняет запрос и будущие имена до выполнения, обычный оркестратор
  останавливает лабу/CT и паркует слот. Worker последовательно снимает ноды,
  сохраняет checkpoints, использует бюджет агента с запасом и публикует все записи
  каталога одной транзакцией. GET отдаёт running/done/failed. Запуск того же
  workspace во время capture блокируется; старая stopped-сессия после нового
  запуска не может снять чужое по времени содержимое проекта.
- Checkpoints продолжаются после перезапуска worker. При потерянном ответе после
  создания файла операция безопасно завершается ошибкой без публикации каталога;
  повтор failed-capture использует новые имена. Готовые непривязанные файлы не удаляются.
- Каталог = `IMAGES_FILE` + БД, изолирован по сайту, читается без перезапуска.
  Свойства и разрешения производного наследуются от базы. Retired остаётся
  доступен старым определениям; PATCH меняет только публичные метаданные.
- `supersedes` связывает предыдущее снятие того же автора/лабы/ноды, даже если автор
  перед новым снятием снова выбрал базовый или чужой образ.
- `capture: false` выставлен в примерах для `lab-uplink` и `linux-switch`.
  Feature/options объявляются по capabilities, авторские запуски размещаются
  только на подходящих узлах. Контракты и ответ плагину обновлены.

## В. Плагин 0.15.0

- Запуск из редактора сохраняет черновик и открывает авторский viewer; переиспользуются
  Session, Stage, Consoles, xterm/noVNC и шлюз. В транспорт добавлена авторская
  адаптация, обычный интерфейс студента работает с прежним API.
- Диалог снятия показывает запущенные QEMU-ноды без `capture: false`, выбор,
  названия/описания и подсказку про machine-id, SSH keys, DHCP identity, shell history.
- По done сервер заменяет только выбранные image в черновике. Сохранение,
  публикация и применение результата используют общую блокировку; применение
  сравнивает исходное определение. Конкурентная правка не затирается.
  Ожидание можно продолжить после перезагрузки той же вкладки через sessionStorage;
  состояние операции хранится в менеджере.
- Палитра содержит базовые/featured, свои последние версии, чужие группы по
  Moodle-авторам с описанием, базой и поиском. Поиск раскрывает совпавшие группы.
  Свои retired видны отдельно для управления, их нельзя добавить как новую ноду.
- `mod/gns3lab:manageimages` — системное право manager. External API проверяет
  контекст, `managelabs`, авторство и отдельно manageimages для featured. Пользователь
  и сессия определяются сервером; node_id сверяется с топологией. Возвращаемые данные
  описаны строгими external-структурами. Privacy API дополнен данными авторского снятия.
- Mock-менеджер реализует authoring, delayed capture, сбой, каталог, supersedes и PATCH.
  UI-harness использует его через локальный Moodle-посредник; этот посредник не
  заменяет проверку настоящих Moodle capabilities и БД.
- AMD build и source maps обновлены запасным сборщиком harness. В старом VNC smoke
  проверка текстовой консоли ожидала `R1#`, хотя текущая QEMU-фикстура R1 получает
  Linux prompt. Проверяется баннер консоли R1; проверки xterm, snippets и font сохранены.

## Г. Установка

- `install/check-derived-images.py` — отдельная команда только чтения, JSON/exit code:
  относительный backing, существующая самостоятельная база, отсутствие цепочки
  производных/симлинков, `0444`, GNS3 MD5-sidecar; с `--images-file` — SHA-256 баз.
- README описывает неизменяемость баз и слоёв, новое имя при обновлении, запрет
  ручного удаления готовых слоёв и команду проверки.
- `SOURCE_FILES` и `compatibility.components` обновлены вместе с компонентами.
  Явный allowlist сборщика сохранён.

## Уточнения контракта и долги

1. У снимаемой базы требуется приватное поле `sha256: "sha256:<64 hex>"` в
   `IMAGES_FILE`: хеш вычисляет администратор при установке файла. Без него обычные
   запуски разрешены, снятие отклоняется как `not_capturable`. Менеджер сам CephFS
   не читает и новых прав на хранилище не получает.
2. Добавлен поиск авторского запуска `GET /sessions?user_id=&library_lab_id=` и
   поле `capture_nodes` — кандидаты из сохранённого снимка топологии, доступные и
   после остановки. Список активностей курса авторские запуски не включает.
3. У существующего API агента/слота нет удаления отдельного проекта. Прежний каталог
   при смене `lab_def` остаётся рядом с новым. Долг записан в AGENT_REQUESTS §6;
   новый разрушительный маршрут не вводился.
4. Атомарность относится к каталогу БД. После сбоя или потери ответа могут остаться
   готовые файлы без записи каталога. Автоматической физической очистки, общей квоты
   и seal нет — это оставленные дизайном следующие этапы.
5. Совместимость linked clone над производным образом не доказана локальными тестами.
   На самостоятельный `qemu-img convert` реализация автоматически не переключается.

## Приёмка владельцем на стенде

1. **До включения UI:** GNS3 2.2.61 принимает производный qcow2 с относительным
   backing, создаёт linked clone, нода стартует, в слоте три уровня backing-chain.
   Если нет — остановиться и согласовать запасной standalone convert.
2. RO-каталог образов работает с готовым `.md5sum`, GNS3 не требует других записей.
3. Автор настраивает Debian, сохраняет образы; размер слоя соответствует изменениям,
   каталог менеджера отдаёт новые id, backing указывает на базу, не на другой d-образ.
4. После публикации студент получает настройки; продолжение его проекта работает
   в другом слоте. Студенты старой версии продолжают свои прежние проекты.
5. Второе снятие сохраняет изменения обоих запусков и снова имеет один слой над базой.
6. При искусственно оставленном `mp1` запрос даёт STUDENT_DIR_BUSY без копирования.
7. Копирование/rebase/хеширование слоя 1–5 ГиБ укладывается в LAB_CAPTURE_TIMEOUT.
8. В Moodle проверить реальные роли автора/manager/студента, запрет правки чужих
   метаданных, manageimages для featured, две вкладки с правкой/публикацией во время
   снятия, телнет/VNC авторского запуска и повторное открытие редактора.
9. До запуска обновлённого менеджера применить миграцию, заполнить SHA-256 снимаемых
   баз и выполнить установочную проверку каталога. Обновлять базовые файлы на месте нельзя.
