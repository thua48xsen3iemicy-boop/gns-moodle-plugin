# TASK-2 — согласованный диск гостя при снятии образа

Доработка PR #82, ветка `feature/derived-images` (продолжать в ней, отдельными коммитами по компонентам). Правила —
`../../AGENTS.md`; основа — `DESIGN.md`, `TASK.md`, `REPORT.md` этой папки и CONTRACTS §2.8.

## Проблема

1. **Диск снимается «выдернутым из розетки».** `POST /sessions/{id}/capture` сразу ставит `stop_requested`; остановка лабы
   (`nodes/stop` GNS3, `on_close` по умолчанию) гасит QEMU без выключения гостя. Грязный кеш страниц гостя (обычно
   последние 5–30 с работы) в `hda_disk.qcow2` не попадает, ФС — как после аварии. Свежая правка конфига может пропасть.
2. **Кандидаты не те.** `capture_nodes` — ноды со статусом `started` в последнем снимке. Нода, которую автор правильно
   выключил изнутри (`poweroff`) перед сохранением, из списка пропадает, хотя её диск — как раз самый надёжный.

## Решения (не пересматривать без владельца)

- Перед остановкой сессии каждая **выбранная и работающая** нода выключается **изнутри гостя**: QGA `guest-shutdown`
  (powerdown), затем ожидание статуса `stopped` в GNS3. Выключенная нода снимается как есть.
- Нельзя выключить штатно (нет QGA, гость не ответил, тайм-аут) — снятие **не начинается**: сессия остаётся
  `running`, автор видит, какие ноды мешают, и либо выключает их сам, либо повторяет запрос с `force: true`
  (снять как есть, с предупреждением о возможной потере последних изменений).
- Кандидат на снятие — QEMU-нода с `capture` ≠ `false`, **которая хоть раз запускалась в этом проекте** (у неё есть диск),
  независимо от текущего статуса.

## Задача А — слот (`slot/`) и контракт

1. Маршрут `POST /v1/labs/{project_id}/nodes/{node_id}/shutdown` (асинхронная операция, как остальные: `202` +
   `operation_id`, идемпотентность по существующим правилам). Только `kind: "qemu"`. Нода уже `stopped` — успех сразу.
   Иначе — `guest-shutdown` через существующий QGA-клиент (`api/qga.py`), затем опрос статуса ноды в GNS3 до `stopped`
   не дольше `timeout` из тела (`{"timeout": 30..300}`, по умолчанию 120).
2. Исходы операции: `stopped` · ошибка `GUEST_AGENT_UNAVAILABLE` (канал QGA не отвечает) · `GUEST_SHUTDOWN_TIMEOUT`
   (команда принята, нода не остановилась). Ноду при ошибке **не** гасить принудительно.
3. Возможность `guest-shutdown` в `features` (`GET /v1/capabilities`) и в реестре CONTRACTS §7; маршрут — в §4
   рядом с остальными маршрутами нод, коды — в §4.4.
4. Тесты на подделках GNS3/QGA: уже выключена, штатное выключение, нет QGA, тайм-аут, не-QEMU нода.
5. Версия `slot/release.json`; `SOURCE_FILES`, `compatibility.components` — если затронуты.

## Задача Б — менеджер (`manager/`) и контракт

1. **Запускавшиеся ноды.** Хранить в рабочей копии (`workspaces`, новая миграция `010_*`) множество имён нод, которые
   хоть раз были `started` в этом проекте: пополнять при каждом опросе статусов. Проект продолжается между
   сессиями — множество тоже. `capture_nodes` в объекте авторской сессии — из этого множества с фильтром
   `kind: "qemu"` и `capture` ≠ `false`, плюс текущий статус: `[{"name", "status"}]` (поменять тип поля в §2.3/§2.8,
   плагин в той же ветке, совместимость со старым форматом не нужна — PR не выпущен).
2. **Тело `capture`:** новое необязательное поле `force: bool` (по умолчанию `false`). Нода не из `capture_nodes` —
   `422 lab_invalid`, код `never_started` (вместо будущего `CAPTURE_NODE_MISSING` от агента).
3. **Новый этап `quiesce` до остановки** для сессии `running`: по каждой выбранной ноде со статусом `started` —
   `shutdown` в слоте (параллельно, общий предел времени). Все `stopped` — дальше как сейчас (`stop_requested`,
   агент). Хоть одна ошибка и `force: false` — снятие `failed` с `error.code` `GUEST_NOT_STOPPED`,
   `retryable: true`, `nodes: [{"name", "reason"}]` (`reason` — код слота); **сессия не останавливается**, уже
   выключенные ноды остаются выключенными. С `force: true` — ошибки выключения не мешают, но имена таких нод
   записать в результат снятия (`forced: [...]`).
4. **Остановленная сессия.** Ноды, которые в последнем снимке перед остановкой были `started`, погашены остановкой лабы.
   Без `force` — `409 guest_not_stopped` с их списком (сообщение: «запустите лабу снова и сохраните из работающей,
   либо сохраните как есть»); с `force` — как сейчас, имена в `forced`.
5. Слот без `guest-shutdown` (маршрут `404`) — все работающие ноды считаются не выключенными штатно (`reason`
   `GUEST_SHUTDOWN_UNSUPPORTED`): без `force` снятие не идёт.
6. В опубликованном образе: `derived.forced: true`, если слой снят без штатного выключения (плагин показывает
   предупреждение рядом с образом). Поле — в §2.8.
7. Тесты: кандидаты после `poweroff` в госте, сохранение множества между сессиями, quiesce успех / частичный сбой
   (сессия жива) / `force`, остановленная сессия с и без `force`, слот без маршрута.

## Задача В — плагин (`plugin/`)

1. Окно «Сохранить с образами»: список из нового `capture_nodes`, статус каждой ноды. Подпись: работающие ноды будут
   **выключены изнутри** перед снятием; совет выполнить `sync`/`poweroff` вручную, если в госте нет агента QGA.
2. Ответ `GUEST_NOT_STOPPED` / `409 guest_not_stopped`: показать, какие ноды и почему (без QGA, тайм-аут), кнопки
   «Повторить» и «Сохранить как есть» (`force: true`) с явным предупреждением о потере последних изменений.
3. Палитра: значок-предупреждение у образа с `derived.forced`.
4. Mock-менеджер: `quiesce` с успехом, частичным сбоем и `force`; новые `capture_nodes`. `ui-harness`: сценарии для
   всех трёх веток и для ноды, выключенной изнутри (остаётся в списке).
5. `version.php`, строки `lang` (en/ru).

## Что проверит владелец на стенде

1. Debian с `qemu-guest-agent`: изменить файл, сразу «Сохранить с образами» — гость выключается штатно (в журнале
   гостя — нормальное завершение), изменение есть в новом образе.
2. Гость без QGA: снятие не начинается, сессия жива; `poweroff` вручную — нода остаётся в списке и снимается.
3. «Сохранить как есть» без QGA — образ публикуется с предупреждением.
4. Сохранение из остановленной сессии — предложение запустить снова или сохранить как есть.
