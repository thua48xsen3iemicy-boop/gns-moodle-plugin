# TASK — разностные образы QEMU (сохранить лабу с преднастроенными образами)

Ветка исполнителя: `feature/derived-images` от свежего `main`. Каждый компонент — отдельный коммит (`../../AGENTS.md`).
С владельцем — по-русски; код, комментарии и коммиты — по-английски.

**Источники правды** (читать до начала, в этом порядке):
1. `docs/derived-images/DESIGN.md` — зачем, решения владельца, варианты хранения. Целиком.
2. `manager/docs/CONTRACTS.md` — §2.8 целиком; точечно §2.2 (поле `instance_id`, `options`), §2.3 (поле `mode`),
   §2.5 (новые коды), §5 (абзац «Снятие слоя образа»), §7 (`image_capture`, `images_capture`). Оглавление — `grep -n '^#'`.
3. `manager/docs/AGENT_REQUESTS.md` §6 — маршрут агента.

Если по ходу работы контракт оказывается неверным или неполным — правь его в том же коммите, что и код, и отметь в
отчёте. Если документы противоречат друг другу — спроси владельца, не выбирай сам.

## Коротко, что строим

Автор лабы в редакторе библиотеки запускает лабу (**авторский запуск**), донастраивает QEMU-ноды и нажимает
«Сохранить с образами». Менеджер останавливает запуск, агент узла снимает диск каждой выбранной ноды
(`hda_disk.qcow2` из проекта на CephFS), пересаживает его на базовый образ администратора и кладёт в
`IMAGES_DIR/QEMU/d-<12 hex>.qcow2`. Плагин заменяет образы этих нод в черновике версии лабы. Слот не меняется.

## Решения (не пересматривать без владельца)

- Черновиков образов нет: единица работы — лаба библиотеки, образы меняются в её черновике версии.
- В каталог образов пишет **только агент**. Каталог образов в слотах остаётся RO; новых точек монтирования нет.
- У производного образа ровно один backing — образ из `IMAGES_FILE`, имя относительное. Повторное снятие —
  безопасный `qemu-img rebase` на базу (без `-u`). Файлы образов неизменяемы, удаления нет, только `retired`.
- Снятие одного запроса — «все или ни одного» для каталога менеджера.
- Права: запуск и снятие — `mod/gns3lab:managelabs`; `featured` — новое `mod/gns3lab:manageimages` (контекст системы).
- Видимость: «Мои образы» раскрыты, «Образы других авторов» — свёрнуты, группы по автору, с описанием и поиском,
  `featured` — в основной палитре.

## Задача А — агент узла (`agent/`)

1. `GET /capabilities`: `images_capture: true` (только если задан `LAB_IMAGES_DIR` и есть `qemu-img`) и
   `capture_timeout_seconds` (`LAB_CAPTURE_TIMEOUT`, по умолчанию 900, пределы 60–3600).
2. `POST /images/capture` строго по AGENT_REQUESTS §6: модель `extra="forbid"`, `strict=True`; имена файлов —
   один компонент пути `[A-Za-z0-9][A-Za-z0-9._-]{0,127}\.qcow2`, `image_file` — `d-[0-9a-f]{12}\.qcow2`.
3. Проверка «каталог студента не подключён ни к одному CT узла» — тем же способом, которым агент уже узнаёт `mp1`
   слотов; не изобретать второй.
4. Поиск диска только по `.gns3` проекта; открытие файлов без следования симлинкам (`O_NOFOLLOW`, проверка, что
   реальный путь внутри каталога студента). `qemu-img` вызывать списком аргументов, без shell, с тайм-аутом.
5. Временный файл `.<image_file>.part` в `QEMU/`, `rename` без перезаписи (`os.link` + `unlink` или проверка
   под блокировкой), `.md5sum` в формате GNS3, `0444`. Уборка `.part` старше тайм-аута — при старте и перед каждым снятием.
6. Коды ошибок — из AGENT_REQUESTS §6; добавь их в таблицу кодов `agent/README.md`.
7. Тесты: подделка `qemu-img` (скрипт в `PATH` теста, отвечает JSON `info` и пишет файлы), случаи: первое снятие,
   повторное (`parent_file` ≠ `base_file`, ожидается безопасный rebase), неверный backing, неверный sha256 базы,
   превышение размера, симлинк, каталог подключён к CT, файл уже есть, нет ноды в `.gns3`.
8. Версия агента — `1.3.0` (`version=` в `agent/agent.py`, заголовок `README.md`).

## Задача Б — менеджер (`manager/`) и контракт

   посмотри, есть ли для этого средство у агента или слота. Если нет — **не изобретай** маршрут молча: опиши в
   `AGENT_REQUESTS.md`/`SLOT_REQUESTS.md`, что нужно, а в менеджере пока начинай новый проект с новым `project_id`

4. `POST|GET /api/v1/sessions/{id}/capture`: остановка сессии обычным путём оркестратора, затем последовательный

5. Каталог: `GET /api/v1/images` = `IMAGES_FILE` ∪ производные из БД (без перезапуска), свойства — от базы;

   Проверка лабы (`validate`) принимает `id` производных образов как обычные.
6. `PATCH /api/v1/images/{id}`.
7. `image_capture` в `info.features` и `mode` в `info.options` — только при агенте с `images_capture` (§1.3).
8. Тесты в `tests/` на подделках (`tests/fakes.py` — расширить агента): авторский запуск и его ключ, конфликт
   сочетаний полей, снятие успех/сбой посередине (ни одного образа в каталоге), повтор `capture`, каталог и лимиты,
   `PATCH`. Тесты PostgreSQL — по образцу существующих (пропускаются без `DATABASE_URL`).
9. Версия — `0.14.0` (`lab_manager/__init__.py`, заголовок `README.md`); `PLUGIN_REQUESTS.md` — короткий ответ плагину
   со ссылкой на §2.8.

## Что проверит владелец на стенде

1. **Главное, до остального:** GNS3 2.2.61 принимает как образ QEMU файл с относительным backing file и делает над ним
   linked clone; нода стартует; `qemu-img info --backing-chain` в слоте — три уровня. Если нет — остановить работу над
   UI и вернуться к владельцу (запасной вариант — `qemu-img convert` в самостоятельный файл).
2. GNS3 не пишет рядом с образом ничего, кроме `.md5sum` (каталог RO), и не ругается на готовый `.md5sum`.
3. Авторский запуск: донастроить Debian, «Сохранить с образами», в `IMAGES_DIR/QEMU` появился `d-*.qcow2` размером
   с изменения, а не с образ; `GET /images` его отдаёт.
4. Студент на опубликованной версии получает преднастроенную ноду; продолжение его проекта в другом слоте.
5. Повторное снятие той же ноды: новый образ, backing — снова база (не прежний слой), изменения обоих сохранений на месте.
6. Студент, начавший на старой версии лабы, продолжает работу после публикации новой.
7. Снятие при каталоге автора, всё ещё подключённом к CT (искусственно), — `STUDENT_DIR_BUSY`, ничего не скопировано.
8. Время снятия слоя 1–5 ГиБ на CephFS укладывается в `LAB_CAPTURE_TIMEOUT`.
