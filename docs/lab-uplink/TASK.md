# TASK — выход лабы в интернет (узел «Интернет»)

Ветка исполнителя: `feature/lab-uplink` от свежего `main`. Каждый компонент — отдельный коммит (`../../AGENTS.md`).
**Сервер PPPoE (BRAS) в эту задачу не входит**: его ставит владелец отдельно. Здесь — всё до него.

## Схема

```
лаба: R1 ─┐
      R2 ─┼─ узел «Интернет» (QEMU, образ images/lab-uplink) ── adapter uplink_port
      R3 ─┘   DHCP + NAT в LAN-портах                              │
                                                                   │ GNS3 cloud node → eth1 слота
слот (LXC): eth0 — служебная сеть (как сейчас), eth1 — без IP ──────┘
узел Proxmox: net1 слота → мост с тегом INET_VLAN → общий VLAN всех узлов → BRAS (PPPoE, NAT) → интернет
```

## Решения

| № | Решение | Почему |
|---|---|---|
| 1 | Вторая сетевая карта `net1` — в шаблоне слотов, клоны наследуют её через `pct clone` | Одинакова у всех слотов; агент слоты не создаёт и не меняется |
| 2 | После клонирования `net1` переписывается без `hwaddr` | Клон может унаследовать MAC шаблона; в общем VLAN MAC должен быть уникален |
| 3 | MAC внешнего порта узла «Интернет» задаёт **слот** из `SLOT_UPLINK_MAC` (`slot.env`), значение генерирует `lab-provision` из VMID | Одна и та же лаба в разных слотах иначе получит одинаковый MAC от GNS3, и PPPoE сломается. Слоту не нужно знать свой VMID |
| 4 | Внешний порт помечается в `NodeSpec` полем `uplink_port` (только `qemu`, `0 ≤ uplink_port < adapters`, не больше одного узла на лабу) | Роль узла слоту иначе не передать (`kind` — только `qemu`/`iou`/`vpcs`). Поле отсутствует у обычных узлов: канонический JSON и `lab_revision` прежних лаб не меняются (как у `console`, `nvram_config`) |
| 5 | Узел GNS3 `cloud`, привязанный к `eth1`, и линк к нему слот создаёт **сам**; в манифесте их нет | Манифест описывает лабу, а не устройство слота. Слот исключает этот узел из своих проверок инвентаря |
| 6 | Узел «Интернет» без консоли для всех: `"console_type": "none"` в `images.json`, как у Linux-коммутатора | Механизм уже есть (менеджер 0.8.1, `docs/linux-switch-integration/PLAN.md`) |
| 7 | В LAN-портах узла адреса из `198.18.0.0/15` (по `/24` на порт) | Диапазон для тестов (RFC 2544): не пересекается с серыми пулами конструктора лаб |
| 8 | Реквизиты PPPoE на этом этапе общие для всех: задаются при сборке образа, в Git не попадают | Изоляцию дают фильтр на мосту и BRAS, а не пароль. Реквизиты на каждый слот — следующий этап |

Не делаем: сервер PPPoE, реквизиты на каждый слот, ограничение скорости и журналы NAT (это BRAS), редактор лаб в плагине
(узел «Интернет» добавляется как обычный образ; отметку `uplink_port` в редакторе — отдельной задачей, если понадобится).

## Задача А — установка (`install/`)

Читать: `install/AGENTS.md`, в `install/lab-provision` — `cmd_template`, `cmd_clone_slot`, `net0()`, `render_slot_env`;
`install/lab.conf.example`; раздел про создание CT в `install/README.md` (по оглавлению).

1. Параметры в `lab.conf.example`: `INET_BRIDGE` (мост Proxmox) и `INET_VLAN` (тег). Оба пустые — `net1` не создаётся,
   поведение как сейчас.
2. `cmd_template`: `--net1 name=eth1,bridge=$INET_BRIDGE,tag=$INET_VLAN,ip=manual,firewall=1`.
   `cmd_clone_slot`: переписать `net1` без `hwaddr`, как это уже делается с `net0`. Шаблон, созданный раньше без `net1`, —
   понятная ошибка с подсказкой (`pct set <шаблон> -net1 …`), а не молчание.
3. `render_slot_env`: `SLOT_UPLINK_MAC` — локально администрируемый unicast `02:6c:61:XX:XX:XX`, где младшие три байта —
   VMID слота (уникален в кластере). Детерминированно: повторный запуск даёт то же значение.
4. Фильтр на мосту узла Proxmox — скрипт `install/lab-uplink-filter` (nftables, семейство `bridge`), параметры — мост, тег,
   `BRAS_MACS`: от портов слотов в VLAN — только `0x8863`/`0x8864` с получателем MAC BRAS или `ff:ff:ff:ff:ff:ff`
   (PADI); к портам слотов — только `0x8863`/`0x8864` от MAC BRAS; всё прочее отбросить. Порт к физической сети (аплинк
   узла) и порты BRAS фильтр не трогает. Идемпотентный, со сбросом своей таблицы; `--check` печатает правила без применения.
5. Тесты в `install/tests` (по образцу существующих тестов `lab-provision`): строка `net1` шаблона и клона, MAC из VMID,
   пустые параметры — нет `net1` и нет `SLOT_UPLINK_MAC`. Для фильтра — сверка сгенерированного набора правил.
6. `install/README.md`: параметры, порядок (фильтр на каждом узле до первого запуска лаб с интернетом), проверка.

## Задача Б — слот (`slot/`) и контракт

Читать: `manager/docs/CONTRACTS.md` §4.1, §4.2, §7; `slot/api/models.py`, `slot/api/labs.py`, в `slot/api/lifecycle.py` —
`validate_topology` и место сверки инвентаря рядом (около строки 500); `slot/api/health.py`; `slot/api/facts.py` —
`adapter_macs`; `slot/slot.env.example`. Остальное — по необходимости.

1. Контракт (тот же коммит, что и код; `manager/docs/CONTRACTS.md` §4.2 и §7): `NodeSpec.uplink_port` — описание по решению 4;
   возможность `uplink` в `features` слота. Слот объявляет её, только когда `SLOT_UPLINK_MAC` задан и корректен и у слота
   есть интерфейс `eth1`.
2. `models.py`: поле и проверки (только `qemu`, в пределах `adapters`, один узел на билет). Отсутствует — в сериализации нет,
   как `console`.
3. `labs.py`: у узла с `uplink_port` задать свойство `mac_address` так, чтобы порт `uplink_port` получил `SLOT_UPLINK_MAC`
   (GNS3 нумерует адаптеры от базового MAC вверх — см. `adapter_macs`; проверить переполнение байта). Создать узел
   `cloud` с зарезервированным именем (например `_uplink`; в `NodeSpec.name` такое имя невозможно — первый символ `_`),
   `ports_mapping` на `eth1`, и линк `uplink_port` ↔ облако. Билет с `uplink_port` при выключенной возможности — 422 с
   понятной причиной, проект не создаётся.
4. Жизненный цикл: сверка инвентаря, `validate_topology`, факты, L1, консоль не должны учитывать `_uplink` и его линк и не
   должны считать их «чужими». При продолжении проекта узел и линк уже есть — не пересоздавать; если их нет —
   ошибка сверки, как для любого расхождения.
5. Тесты `slot/tests`: MAC порта для `uplink_port` 0 и N; переполнение; облако и линк в запросах к GNS3; 422 без
   `SLOT_UPLINK_MAC`; повторный deploy не меняет паспорт; лаба без `uplink_port` даёт те же запросы, что раньше.
6. `slot.env.example`, `slot/README.md` (раздел API), версия слота и манифест — `python3 slot/release.py seal`
   (`slot/AGENTS.md`).

Если узел `cloud` GNS3 2.2.61 не может работать на `eth1` в непривилегированном LXC (нужен сырой сокет), это выясняется
только на стенде: в отчёте отметить как первый пункт проверки, код писать под штатный `cloud` с `ports_mapping`.

## Задача В — менеджер (`manager/`)

Читать: `manager/docs/CONTRACTS.md` §2.6 и §4.2; `lab_manager/labdef.py` (`deploy_ticket`), `lab_manager/images.py`,
`examples/images.json`.

1. Поле `uplink_port` узла лабы проходит из определения лабы (и эталонной `lab_ref`) в `NodeSpec` без изменений, только если
   задано. Проверка лабы (`POST /labs/validate`): не больше одного такого узла, порт в пределах адаптеров, к этому порту

2. Слот без `uplink` в `features` не получает лабу с `uplink_port`: выбор слота это учитывает, как другие возможности (§7).
3. `examples/images.json`: запись `lab-uplink` с `"console_type": "none"`.
4. Тесты менеджера; версия.

## Задача Г — образ узла «Интернет» (`images/lab-uplink/`)

По образцу `images/linux-switch/` (структура, `AGENTS.md`, установка в гостя, тесты). Читать: `images/linux-switch/README.md`,
`images/linux-switch/docs/INTEGRATION.md`. Debian, QGA обязателен (слот требует `qga` у всех QEMU-узлов).

1. Адаптер 0 — внешний (`uplink_port: 0` в лабах по умолчанию), без IP; PPPoE-клиент (`pppd` с `rp-pppoe.so`),
   `persist`, `maxfail 0`, `defaultroute`, `usepeerdns`. Реквизиты — из файла, который пишет сборка образа (`--pppoe-user`,
   `--pppoe-password`), в репозитории — только пример с заглушкой.
2. Адаптеры 1…N — LAN: `198.18.<N>.1/24`, DHCP (`dnsmasq`) со шлюзом и DNS = адрес порта; DNS — пересылка на DNS от PPPoE.
3. `nftables`: NAT (masquerade) в `ppp0`; пересылка только LAN → `ppp0` и ответы; LAN ↔ LAN запрещено; к самому узлу из
   LAN — только DHCP и DNS. TCP MSS clamp по PMTU (MTU PPPoE 1492, у маршрутизаторов лабы 1500).
4. Число LAN-портов берётся из числа адаптеров при загрузке, без правки образа.
5. Тесты без стенда: сгенерированные конфиги `dnsmasq`/`nftables`/`pppd` для 1 и 4 LAN-портов. Если в окружении можно
   создать сетевые пространства имён — сквозной тест с `pppoe-server` (rp-pppoe) в отдельном netns; нельзя — так и написать.
6. `README.md`: сборка, параметры, как подключить в лабу, что видит маршрутизатор лабы (получает адрес по DHCP).

## Что проверит владелец на стенде

Без BRAS (сервер PPPoE ещё не поднят):

1. `lab-provision`: у нового шаблона и клонов есть `net1` в нужном VLAN, MAC клонов разные; `slot.env` — свой `SLOT_UPLINK_MAC`.
2. `GET /v1/capabilities` слота: `uplink` в `features`.
3. Лаба: маршрутизатор + узел «Интернет». В GNS3 слота есть `_uplink` на `eth1`, MAC внешнего порта = `SLOT_UPLINK_MAC`.
   Та же лаба в двух слотах — MAC разные.
4. `tcpdump -e -i <мост> ether proto 0x8863` на узле Proxmox: PADI от узла «Интернет» видны, с правильным MAC.
5. Маршрутизатор лабы получает по DHCP адрес `198.18.1.x` и шлюз.
6. Фильтр: из слота кадры не-PPPoE в VLAN не проходят (`ping`/`arping` с `eth1` слота на другой слот — тишина).
7. Консоль узла «Интернет» закрыта в плагине и в `console-tickets` (`403 console_disabled`).

С BRAS (после его установки): сессия поднимается, `ping 1.1.1.1` и HTTPS с маршрутизатора лабы; большие страницы
грузятся без зависаний (MSS clamp); две лабы на разных узлах Proxmox работают одновременно.
