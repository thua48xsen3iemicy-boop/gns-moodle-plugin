## R1 — P2: прямой запуск выбирает интерпретатор из PATH

`install/lab-provision:1` использует `#!/usr/bin/env bash`. При документированном
прямом запуске абсолютного пути скрипта оболочка выбирается из PATH до исполнения
защищённого dispatcher. Если PATH содержит каталог проверяемого пакета с
исполняемым bash, этот файл запускается вместо доверенной оболочки.

Воспроизведение: создать временный каталог с bash, который через /bin/sh
создаёт sentinel и выходит с кодом 99. Запустить абсолютный путь lab-provision
с аргументами `release verify --help` и PATH, указывающим на этот каталог.
Получено: `exit_code=99`, `untrusted_bash_executed=True`.

Существующий тест `test_payload_executables_in_path_are_never_selected`
вызывает /bin/bash явно и поэтому не покрывает реальный прямой запуск.
Закрепить доверенный абсолютный интерпретатор launcher и добавить регрессию
прямого вызова. Область замечания — именно выбор bash через PATH;
универсальная защита от произвольного окружения вызывающего процесса не заявляется.

## R2 — P2: причина отказа builder теряется до удаления CT

`install/release-builder.py:218–220` заменяет ошибку на JSON только с
`error_type`. `install/lab-release.py:125–127` отбрасывает и этот JSON,
возвращая лишь `Command failed: pct exit=1`. Затем ветка finally
(`lab-release.py:1017–1023`) выполняет cleanup; при успехе builder удаляется.
Recovery metadata описывает ресурсы, но не сохраняет причину сбоя сборочного шага.

Воспроизведение настоящего command() с подменой результата subprocess:
два CalledProcessError с разным безопасным stderr (ошибка download и ошибка
readonly smoke) дают один и тот же итог:

```text
wheel_download: Command failed: pct exit=1
readonly_smoke: Command failed: pct exit=1
```

Это модель канала передачи ошибки, не запуск pip или LXC. Потеря причины
подтверждена также чтением helper, host wrapper и порядка cleanup.
Оператор не может определить причину отказа по сохраняемому результату.

Передавать безопасную структурированную диагностику: компонент, этап,
стабильный код, ограниченное очищенное пояснение. Host должен сохранить её
до cleanup и не заменять первичную ошибку ошибкой очистки. Не выводить сырые
pip logs, окружение, credentials или секретные аргументы команд.
Добавить проверки различимости отказов download/install/smoke, сохранения
диагностики после удаления builder и при дополнительном отказе cleanup.
