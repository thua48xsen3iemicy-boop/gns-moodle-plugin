# Гость с графической консолью: аппаратный курсор и полный экран

Образ Linux с рабочим столом для узла с `console_type: vnc` (QEMU VNC, в браузере noVNC). Написано для Debian 13 с XFCE
на X11. Скрипт `gns3lab-vnc-resize` проверен только на подставных `xrandr` и `xev`, на настоящем госте — по списку ниже. Плагин 0.47.0 и выше: кнопка «Во весь экран» в меню экрана
(язычок у правого края экрана).

Что даёт:

- **указатель без задержки.** Если гость рисует курсор аппаратно, QEMU отдаёт его форму noVNC, и браузер рисует указатель
  сам, без пути «браузер → шлюз → слот → QEMU → гость → кадр → обратно». Программный курсор гостя приходит картинкой
  экрана и отстаёт от руки;
- **полный экран 1:1.** В полноэкранном режиме плагин просит у узла разрешение монитора в физических пикселях
  (1920×1080 на Full HD, и при масштабе Windows 125 % тоже), не больше 2560×1440; при выходе — прежнее разрешение.
  QEMU передаёт просьбу видеоадаптеру virtio-gpu как новый «рекомендуемый» режим, а гость должен на него переключиться.

## 1. Аппаратный курсор

Пакетов ставить не нужно, но должны совпасть три условия.

1. Видеоадаптер `virtio-vga` и модуль `virtio_gpu`. Адаптер слот добавляет сам каждой vnc-ноде (`-vga virtio`),
   модуль есть в стандартном ядре `linux-image-amd64`.

   ```sh
   lsmod | grep virtio_gpu
   ls /sys/class/drm            # card0-Virtual-1 или похожий
   ```

2. Xorg работает с драйвером `modesetting` (входит в `xserver-xorg-core`), а не `fbdev` или `vesa`: с ними курсор
   программный.

   ```sh
   grep -E '\((II|EE)\) (modeset|fbdev|vesa)' /var/log/Xorg.0.log   # нужны строки modeset(0)
   ```

   В `/etc/X11/xorg.conf` и `/etc/X11/xorg.conf.d/` не должно быть `Driver "fbdev"`/`"vesa"` и `Option "SWcursor"`.
   `xserver-xorg-video-qxl` и `spice-vdagent` не нужны.

3. Курсор не крупнее 64×64: больше аппаратный курсор virtio-gpu не берёт, и Xorg молча рисует программный. Размер
   темы 24–32 (по умолчанию) подходит.

Как понять, что работает: указатель в noVNC двигается без задержки и меняет форму (I-образный над текстом). Плагин для
этого не меняется: noVNC рисует курсор, который присылает QEMU.

## 2. Разрешение под полный экран

На X11 гость сам на новый режим не переключается. Это делает `gns3lab-vnc-resize` из этого каталога: он работает в сессии
пользователя, ждёт событий RandR и переключает экран, **только когда изменился рекомендуемый режим** (это и есть просьба
noVNC). Режим, который выбран вручную или восстановлен XFCE при входе, он не трогает: студент входит в своём обычном
разрешении.

```sh
apt-get install -y x11-xserver-utils x11-utils          # xrandr и xev
install -m 755 gns3lab-vnc-resize /usr/local/bin/
install -m 644 gns3lab-vnc-resize.desktop /etc/xdg/autostart/
```

Обычное разрешение задайте под пользователем студента: «Настройки → Дисплей», сохранить. Его XFCE восстанавливает при
входе, и к нему плагин возвращает узел после полного экрана (плагин запоминает размер экрана перед входом в полноэкранный
режим, в том числе на случай перезагрузки страницы).

Если после полного экрана XFCE сам возвращает сохранённое разрешение или показывает окно «подключён дисплей», в «Дисплей →
Дополнительно» выберите «при подключении дисплея — ничего не делать» и выключите автоматическое включение профилей.
На стенде это не проверялось.

## 3. Панель XFCE — внизу

В полноэкранном режиме Chrome и Edge при наведении мыши на верхний край монитора показывают кнопку выхода (крестик в
кружке) и перехватывают щелчки под ней. Страница убрать её не может, а панель XFCE по умолчанию как раз сверху. Перенесите
панель вниз под пользователем студента: правый щелчок по панели → «Панель» → «Параметры панели» → снять «Заблокировать
панель», перетащить за край вниз и снова заблокировать (или задать то же в `/etc/xdg/xfce4/panel/default.xml` до первого
входа пользователя).

## 4. Что проверить на стенде

Плагин 0.47.0, узел с этим образом, Chrome или Edge, монитор Full HD.

1. Узел запущен, экран открыт: указатель следует за мышью без задержки и меняет форму над текстом (аппаратный курсор).
2. Язычок у правого края экрана → меню: «Ctrl+Alt+Del» и «Во весь экран», кнопки «Вставить» нет.
3. «Во весь экран»: экран занимает весь монитор, через секунду-две гость переходит на 1920×1080 (`xrandr` в терминале
   гостя), картинка чёткая, без масштабирования.
4. В полноэкранном режиме Esc, Win и Alt+Tab уходят в гостя (Chrome/Edge: Keyboard Lock); выход — удерживать Esc или
   «Выйти из полноэкранного режима» в меню язычка. Гость возвращается к прежнему разрешению.
5. На мониторе больше 2K (например, 4K) гость получает 2560×1440, браузер растягивает картинку.
6. Перезагрузка страницы в полноэкранном режиме: после нового подключения гость возвращается к прежнему разрешению.
7. Без `gns3lab-vnc-resize` полный экран работает, но разрешение гостя не меняется, а картинка масштабируется.

Если разрешение не меняется: после «Во весь экран» `xrandr --query` в терминале гостя должен показать новый режим с `+`.
Если `+` у нового режима есть, а режим не переключился, проверьте, что скрипт запущен (`pgrep -af gns3lab-vnc-resize`). Если `+` у нового режима нет, просьба не дошла до гостя: проверьте
`-vga virtio` в параметрах QEMU ноды (`ps ax | grep qemu` в слоте).
