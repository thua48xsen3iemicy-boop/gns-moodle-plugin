# Готовые скрипты для автопроверки

Скрипт преподавателя — команда, которую автопроверка выполняет внутри устройства лабы и сравнивает её вывод с ожидаемым.
Формат — `docs/autochecks/README.md` §7, контракт — `manager/docs/CONTRACTS.md` §2.9 (`scripts`). Каждый файл здесь —
один готовый элемент списка `scripts`: скопируйте его в редакторе лабы (блок «Скрипты преподавателя» или JSON проверок
`"scripts": [ … ]`) и поправьте под свою лабу.

## Что поменять в любом фрагменте

- `node` — имя устройства в вашей лабе. Скрипты выполняются только на QEMU-устройствах с агентом гостя: Linux, Windows,
  MikroTik RouterOS. У Cisco IOL, VPCS и ISP скриптов нет (IOL проверяется по сохранённой конфигурации встроенными правилами).
- `id` — латиница, цифры, `-` и `_`; в лабе не повторяется. `title` видит студент: пишите, *что* должно работать, а не *как*.
- Адреса, имена пользователей и служб — ваши.
- `class` — насколько серьёзен провал: `critical`, `major` (по умолчанию), `minor`, `note`. `group` — раздел отчёта и
  «фокус» лабы: `l1`, `l2`, `addressing`, `gateways`, `routing`, `host`.

## Фрагменты

| Файл | Что проверяет | Где | Что поправить |
|---|---|---|---|
| `nginx.json` | nginx запущен и отвечает `200` на `http://127.0.0.1/` | Linux (systemd, curl) | `node`; другой сервис — имя в `systemctl is-active` |
| `ssh-key.json` | с PC1 на SRV1 входят **по ключу**, без пароля | Linux (OpenSSH) | `node` — откуда, `admin@192.168.10.10` — куда |
| `ping-reachable.json` | из одной группы доступен узел другой | Linux | `node`, адрес |
| `ping-isolated.json` | узел **недоступен**: сети разделены, как требует задание | Linux | `node`, адрес |
| `dhcp-lease.json` | устройство получило адрес по DHCP из нужной сети | Linux (iproute2) | `node`, подсеть в `match` |
| `routeros-dhcp-server.json` | DHCP-сервер на MikroTik выдал хотя бы одну аренду | RouterOS 7 | `node` |
| `windows-service.json` | служба Windows запущена | Windows (PowerShell) | `node`, имя службы |

Пояснения:

- **`ssh-key.json`** выполняется от root, поэтому проверяет ключ root на PC1. Если ключ по заданию у другого пользователя,
  оберните команду: `su -s /bin/sh student -c 'ssh … echo {{nonce}}'`. `BatchMode=yes` запрещает пароль: без ключа
  вход не удастся. SRV1 возвращает маркер `{{nonce}}`, новый в каждой проверке, поэтому заготовка «echo ok» не пройдёт.
- **`ping-*.json`** печатают `reachable` / `unreachable` (`isolated`) и сравнивают по `match`: так «нет связи» различимо от
  ошибки самого скрипта. Ping через сеть дополняет встроенное правило `unreachable` (таблицы маршрутов), а не заменяет его:
  ping видит и фильтры, и NAT.
- **`dhcp-lease.json`** ищет адрес с флагом `dynamic` — так iproute2 помечает адрес от DHCP. Имя интерфейса не указано:
  в лабах со случайными именами интерфейсов оно заранее неизвестно.
- **`windows-service.json`** нужен слот 0.27.0 и новее (`exec-shell`); на старом слоте скрипт PowerShell пропускается.

## Как писать свои

- **Скрипт только читает.** Он выполняется от root (на Windows — от SYSTEM) в лабе студента и может её сломать.
- **Ограничьте время самой команды** (`curl -m 5`, `ping -W 2`, `ssh -o ConnectTimeout=5`) и задайте `timeout` с
  запасом: не уложился — провал с причиной «не завершился вовремя».
- **Печатайте короткий однозначный итог** (`active`, `reachable`, число) и сравнивайте его: `match` — регулярное выражение
  RE2 (без обратных ссылок), ищется в выводе; `contains` / `not_contains` — подстроки. Пробелы и переводы строк в конце
  вывода отбрасываются, `\r\n` становится `\n`. Без условий скрипт проходит при коде выхода 0.
- **Проверяйте путь, а не слова.** Если проверяете связь или доступ (SSH, HTTP, файл через сеть), пропустите через него
  `{{nonce}}` и ждите его в ответе.
- **Проверьте до выдачи.** Запустите лабу в элементе курса под тестовым студентом, настройте её как надо и нажмите
  «Проверить»: каждый скрипт должен пройти, его вывод виден преподавателю в отчёте прогона. Потом сломайте то, что
  проверяете, — скрипт должен не пройти. (Проверка прямо в авторском запуске — следующий шаг, `docs/autochecks/README.md` §13.)

Пределы: до 20 скриптов в лабе, `timeout` 1…60 с, сумма всех `timeout` — до 120 с, текст скрипта — до 8000 байт.
Тест `manager/tests/test_check_scripts.py` проверяет, что каждый фрагмент здесь проходит проверку менеджера.
