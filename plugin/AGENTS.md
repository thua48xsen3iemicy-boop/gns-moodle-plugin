# AGENTS.md — mod_gns3lab

Пути ниже — относительно `plugin/`. Общие правила и экономия контекста — в `../AGENTS.md`.

Moodle-плагин (модуль активности) для лабораторных работ в GNS3: студент открывает элемент курса,
видит схему топологии и работает в консолях устройств прямо на странице Moodle.
Лабы запускаются в LXC-слотах Proxmox внешним сервисом (менеджером), консоли идут через отдельный шлюз.

Полное задание, контракты и этапы — в `docs/SPEC.md`. Прочитай его целиком перед работой.

## Параметры проекта

- **Moodle: 5.1** (раскладка с `public/`: плагин ставится в `public/mod/gns3lab`). Если версия другая — спроси, не угадывай.
- PHP: тот, что требует эта версия Moodle.
- Язык общения с владельцем проекта: **русский**. Комментарии в коде и коммиты — на английском (стандарт Moodle).
  Языковые строки: `lang/en` обязательно, `lang/ru` — полный перевод.

## Раскладка репозитория

```
plugin/        корень плагина mod_gns3lab (монтируется в public/mod/gns3lab dev-Moodle)
devtools/      mock-менеджер, docker-compose для dev-окружения, скрипты (создать на этапе 0)
prototypes/    рабочие прототипы UI — эталон поведения, НЕ код для копирования как есть
fixtures/      пример .gns3 (11 нод, все типы линков) и демо «живых» данных
docs/          SPEC.md и прочая документация
```

## Жёсткие правила

1. **Права проверяются только на сервере.** Флаги в JS (`observer` и т.п.) — лишь для отрисовки UI.
   Каждая external function: `validate_parameters` → `validate_context` → `require_capability` → проверка групп/владения.
2. **Moodle не проксирует WebSocket.** Браузер ходит в шлюз напрямую по одноразовому билету.
   Билет Moodle получает у менеджера сервер-сервер. Токены слота и секрет менеджера никогда не попадают в браузер.
3. **Только AMD-модули.** Никаких `<script>` через `$PAGE->requires->js()` для библиотек: на странице RequireJS,
   UMD-сборка xterm.js вызовет анонимный `define()` и сломает страницу. xterm.js и addon-fit кладутся в `amd/src/`
   как сторонние библиотеки и регистрируются в `thirdpartylibs.xml`. CSS — в `styles.css` плагина.
   Третья сторонняя библиотека — `amd/src/novnc.js` (noVNC 1.7.0, ES-модуль; собран `devtools/build_novnc.mjs`, в сессии
   не читай и не правь: шапка файла и `thirdpartylibs.xml` говорят, что в нём изменено).
4. **`amd/build` коммитится** и пересобирается после каждого изменения `amd/src` (`grunt amd` в dev-Moodle).
5. Любое изменение в `db/` (install.xml, access.php, services.php) — подними `version.php` и, если нужно, `db/upgrade.php`.
6. SVG из `.gns3` (`topology.drawings[].svg`) — недоверенные данные. Только через санитайзер по белому списку
   (см. `sanitizeDrawing()` в `plugin/amd/src/stage.js`), никогда `innerHTML` как есть. Весь текст в HTML — через экранирование.
7. Внешние HTTP-вызовы из PHP — только классом `\core\http_client` (или `curl` Moodle), с таймаутами.
   Адрес менеджера, секрет и адрес шлюза — настройки плагина (`settings.php`), секрет хранить как `admin_setting_configpasswordunmask`.
8. Privacy API обязателен: провайдер с `external_location_link` (ID пользователя уходит менеджеру).
9. Не добавляй зависимостей без необходимости. Фронтенд — ванильный JS (как в прототипах), без React/Vue/бандлеров.

## Прототипы: что из них брать

- `prototypes/student-ui.html` — **эталон интерфейса студента**, он уже перенесён в плагин (`lab.php`, 0.5.0): схема с
  уровнями детализации по зуму, колесо действий, консоли панелью / сеткой / окнами, на телефоне — шторка консоли и вход
  в неё щипком. Менять поведение интерфейса — сначала там, потом в модулях. Имитатор IOS в нём — только для демо.
  Раскладка модулей `plugin/amd/src/`:
  `lab.js` (страница: связывает всё остальное), `seat.js` (одно место на лабу: захват, биение, стена, id страницы для вызовов,
  `docs/seat.md`), `session.js` (сессия: кнопки, статус, опрос), `stage.js` (схема: SVG,
  уровни детализации, слои, жесты, выделение), `wheel.js` (колесо), `details.js` (карточка сведений), `consoles.js`
  (раскладки консолей, шторка телефона, панель под терминалом: размер шрифта и закреплённые сниппеты), `console.js`
  (подключение к шлюзу, переподключение), `snippets.js` (команды по виду устройства, группы, без DOM), `snipmenu.js` (меню
  сниппетов и подсказка над кнопкой), `facts.js` (слои L1/L2/L3/OSPF из фактов, без DOM), `consolefacts.js` («увидено в
  консоли»: разбор вывода команд и слияние с фактами менеджера, без DOM, `docs/live-state.md` §8), `consolewatch.js`
  (снимает команды и вывод с буфера xterm), `reveal.js` (режимы `seen` и `fog`: маска открытого, что открывают команды и
  факты, видимая модель и отфильтрованные факты, без DOM, `../docs/lab-constructor/README.md` §2), `model.js` (модель
  `.gns3`), `segments.js` (сегменты `lab/2`: подсеть, адреса, ожидаемые факты и факты предпросмотра, путь сегмента и ноды, которые
  настраивает менеджер, привязка находок менеджера по `path`, без DOM, `../docs/lab-constructor/README.md` §3, §6), `dom.js` (помощники).
  Страница преподавателя «Лабы курса» (0.14.0, `docs/teacher-dashboard.md`): `course.js` (таблица «студенты × лабы», карточка, опрос) и
  `coursefacts.js` (сводка ячейки и данные карточки из `model.buildModel` + `facts.derive`, без DOM; проверка — `devtools/check_coursefacts.mjs`,
  в браузере — `devtools/ui-harness/check_course.js`). Данные — `mod_gns3lab_get_course_overview` (`classes/external/`), состав страницы
  (лабы, группы, студенты) — `classes/local/course_labs.php`, кэш сессий лабы — `classes/local/activity_sessions.php`.
  Оформление — через переменные Moodle (тема Boost/Bootstrap), корень стилей — `.gns3lab-student`; тёмную тему не ломать.
- Колесо действий: Пуск / Стоп / Рестарт узла и пауза линка из прототипа **не перенесены** — в API менеджера таких вызовов
  нет. На их месте «свободные кнопки» («Скоро»), в `lab.js` (`actionsFor`) — для будущих действий, например документации.
- Слой «увидено в консоли» (0.8.0) живёт только на странице: то, что студент выполнил в консоли, разбирается в браузере и
  ложится поверх фактов менеджера до их следующего изменения. В менеджер, слот и оценку оно не уходит, контракт
  `manager/docs/CONTRACTS.md` не меняет. Правила разбора и слияния — `docs/live-state.md` §8; проверка без браузера —
  `devtools/check_consolefacts.mjs`.
- Режимы `seen` и `fog` (0.9.0) прячут от студента часть схемы по маске, которую сервер хранит в `gns3lab_reveal`
  (`classes/local/reveal.php`, `mod_gns3lab_get_reveal`, `mod_gns3lab_reveal`). Это учебный приём, а не защита: топология и
  факты приходят в браузер целиком. Слои и находки строятся по **отфильтрованным** модели и фактам (`reveal.js`
  `layerModel`, `applyReveal`), чтобы текст находки не назвал скрытое; всё, что рисует имя или порт, спрашивает видимое
  состояние узла (`n.state`: `hidden`, `silhouette`, `known`, `open`) и `stage.endShown(конец)`. Проверка без браузера —
  `devtools/check_reveal.mjs`, в браузере — `devtools/ui-harness/check_reveal.js`.
- `prototypes/topology-viewer.html` и `prototypes/console.html` — прототипы прежних версий: слои и сведения о нодах
  живут теперь в `facts.js` и `details.js`, консоль — в `console.js` и `consoles.js`. Редактор лаб (`editor.js`) ещё
  опирается на разметку и стили вьюера.
- Одно место на лабу (0.12.0, `docs/seat.md`): `classes/local/seat.php` решает, кто ведёт лабу студента; `claim_seat` — захват и биение;
  `start_session`, `stop_session`, `get_console_ticket` (свою лабу) и `reveal` зовут `seat::require_seat` и принимают `tabid`.
  Новый вызов, которым студент **меняет** свою лабу или открывает консоль, обязан делать то же и отдавать странице `tabid`
  (`seat.js` `tabId()`, ошибку — в `reportRefusal`). Чтение место не охраняет. Контракт менеджера не затронут.
- Шлюз консолей ведёт менеджер: `../manager/gateway/` в этом же репозитории (MANAGER_REQUESTS §12). Контракт
  браузер ↔ шлюз (билеты, кадры, коды закрытия) меняется только по договорённости с менеджером.

## Dev-окружение

- Moodle — через `moodle-docker` той же версии; `plugin/` монтируется в `public/mod/gns3lab` (bind mount, не симлинк:
  страницы подключают `../../config.php` относительным путём).
- `grunt amd` запускай из каталога плагина внутри дерева Moodle: ESLint ищет `.eslintrc` Moodle по реальному пути файла.
- Настоящий менеджер — `../manager/` в этом же репозитории (нужен Proxmox). Для разработки плагина —
  mock `devtools/mock-manager` (`devtools/README.md`): то же поведение API и поддельная консоль Lab Slot.
  Договорённости с менеджером — `docs/MANAGER_REQUESTS.md` (наши) и `manager/docs/PLUGIN_REQUESTS.md` (его ответы).
- Проверки перед коммитом: `moodle-plugin-ci phpcs` (стандарт moodle), `phplint`, `phpdoc`, PHPUnit и Behat плагина.
- Интерфейс студента без Moodle: `devtools/ui-harness/` (заглушки `core/ajax`, `core/str`, поддельный шлюз, Chromium).
- Режим разработчика Moodle включён, после правок — сброс кэшей (`admin/cli/purge_caches.php`).

## Как работать

- Иди по этапам из SPEC. В конце этапа — краткий отчёт: что сделано, как проверить руками, что осталось.
- Если в SPEC противоречие или не хватает решения — спроси, а не выдумывай контракт.
- Мелкие коммиты с понятными сообщениями. Не коммить секреты, `.env`, дампы БД.
