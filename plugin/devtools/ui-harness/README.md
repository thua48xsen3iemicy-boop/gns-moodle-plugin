# ui-harness — интерфейс студента без Moodle

Открывает страницу студента (`lab.php`) в браузере, не поднимая Moodle, менеджер и шлюз. Для правок интерфейса: схема,
колесо действий, сведения, консоли, телефонная ширина, тёмная тема.

Что настоящее: модули `plugin/amd/src` (собираются Babel в AMD), шаблон `plugin/templates/viewer.mustache`
(рисуется настоящим Mustache со строками из `plugin/lang`), `plugin/styles.css`, демо-лаба `plugin/demo`.
Что подделано: `core/ajax` (сессия в памяти: старт → запуск → работает, остановка), `core/str`, `core/notification`
(`stubs/`) и шлюз консолей (`server.js`, WebSocket `/gw/console/<node_id>`): эхо ввода и приглашение по виду устройства — Cisco IOS
(IOU, маршрутизаторы) `R1#`, VPCS `PC1> `, остальные узлы — Linux `user@pc1:~$ `; `reload` закрывает консоль кодом 4000.
Ответы подобраны так, чтобы слой «увидено в консоли» (`docs/live-state.md` §8) было что показать сразу: `show ip interface
brief`, `show interfaces status` (порт Et0/2 коммутатора выключен), `show vlan brief` (есть VLAN 20, которого нет в фактах), `show spanning-tree` (SW1 — корень VLAN 1 и 10, порт Et0/2
показан заблокированным в VLAN 10, хотя петли в демо нет),
`write memory` / `wr` с `[OK]`, у Linux `ip a`, `ip -br a`, `ip r` и у VPCS `show ip` с другим адресом, чем в фактах.

Canvas проверяется скриптом `node check_canvas.js [--min]` после сборки. Он запускает сервер на 18129,
проверяет независимые вкладки карточки, сохранение выделения после её закрытия, связь VLAN с настоящими
L2-доменами, участников подсети, зарезервированный L4, задания и русский мобильный вид в тёмной теме.
Параллельно открывается исходный `student-ui-canvas.html` с заблокированными внешними ресурсами:
проверяются совпадение палитры, размеров SVG-панели, геометрии карточки и типографики, а также отсутствие
переключателей режимов прототипа в рабочем интерфейсе. Для сравнения обе страницы получают одни и те же
локальные IBM Plex. Проверяются состояния MAC-таблицы, снимок гостей Proxmox и выполнение команды из карточки
через реальную цепочку xterm → шлюз → «увидено в консоли»; у наблюдателя кнопок отправки команд нет.
Для TX → RX, точек портов, шрифтов и линий проверяются 40 сочетаний угла и масштаба. Нужны Playwright и Chromium;
путь к браузеру можно задать через `CHROMIUM_BIN`. Текст заданий в harness — пример описания активности;
в Moodle он приходит через `format_module_intro`, а не из демонстрационного набора.

Консоли студента у наблюдателя (`consoleactivity.js`, manager CONTRACTS §6.3) — `node check_activity.js [--min]`: страница
`?observer` открывает `/gw/console/activity` поддельного шлюза; кадры, которые тест шлёт `POST /gw/activity`
(`{"type": "open"|"input"|"close", "node": …}`), ставят значок студента, мигание и метку последнего ввода; щелчок по значку
открывает консоль; новая страница получает снимок; своя страница студента билета активности не просит.

Закрытая консоль остаётся подключённой (`consoles.js`, `PARK_MAX`) — `node check_park.js [--min]`: команда в консоли SW1,
консоль закрыта и открыта снова — тот же экран, без нового билета и сокета; остановка лабы закрывает соединение.

«Обновить сейчас» и панель слоёв за краем — `node check_hud.js [--min]`: кнопка занята («Collecting…», недоступна,
`aria-busy`) до новых фактов, потом «Updated» и снова «Refresh now»; кнопка `‹` уводит карточку слоёв за левый край
и оставляет язычок с текущим слоем (следит за клавишами 1–4), выбор переживает перезагрузку; то же на ширине телефона.

Пилюльки подсетей L3 на «кривой» конфигурации — `node check_l3stack.js [--min]`: три подсети на кабеле R1–R2 и три
на R2–R3 (одна — неверная маска только у R3) стоят стопкой поперёк кабеля по порядку адресов, подсеть другого интерфейса
R3 остаётся у своего кабеля, пилюльки не перекрываются ни при каком зуме, кабели под L3 видны.

Маршруты на L3 — `node check_routes.js [--min]`: демо-лаба с добавленными маршрутами (`__stub.facts.patchNode(<node_id>,
{routes: [...]})` меняет поля самой ноды): на уровне «Подписи» стрелок нет, кроме стрелок выделенного узла, на уровне
«Адреса» — все; на уровне «Подписи» нет подписей адресов подсетей, щелчок по пилюльке R2–R3 показывает адреса только её
участников и не показывает стрелок, а на «Адресах» подсвечивает стрелки от её узлов и к ним, остальные бледнеют; стрелки по умолчанию PC1/PC2 → R2, R2 → R1, статические R2 ↔ R3, обрывок «?» у
R3 со шлюзом, которого нет; щелчок по стрелке выделяет PC1 и раскрашивает подсети по достижимости (10.2.20.0/24 — туда и
обратно, 192.168.122.0/24 — только туда: у R1 нет обратного маршрута), карточка R3 на L3 — разделы «Маршруты» и
«Достижимость»; светлая и тёмная темы.

Кружок «i» пилюльки VLAN на L2 — `node check_vlaninfo.js [--min]`: щелчок по пилюльке выделяет VLAN и его линии без
карточки, щелчок по «i» и Enter открывают карточку, двойной щелчок — консоль коммутатора.

Вкладки «Панели» и панель за краем — `node check_dock.js [--min]`: колесо над вкладками листает их вбок, Shift+← / Shift+→ докручивают полосу до выбранной вкладки, вкладка
перетаскивается на первое место (порядок держат щелчок и Shift+→), кнопка `»` уводит панель за край и оставляет язычок
с числом консолей и пометкой нового вывода, щелчок по язычку и открытие консоли со схемы возвращают панель.

Адрес шлюза, который браузер не открывает (`ws://` со страницы по https, кривой URL), — `node check_badgateway.js [--min]`:
консоль пишет «The console is unavailable» и не висит в «подключении»; заглушка `?badgateway` отдаёт такой адрес в билете.

«Смонтировать ISO» (manager CONTRACTS §2.12, `docs/iso.md`) — `node check_iso.js [--min]`: пункт «ISO» в колесе QEMU-ноды,
ход сборки, итог с именами приёмников, своя ошибка для пустого каталога; у VPCS-ноды и у наблюдателя пункта нет. Заглушка:
все QEMU-ноды — источники и приёмники, `window.__stub.iso.next = '<код>'` проваливает следующую сборку.

Режим обслуживания (manager CONTRACTS §2.11) — `node check_maintenance.js [--min]`: строка обслуживания с обратным
отсчётом, неактивная кнопка запуска, остаток времени до начала обслуживания, остановка лабы и конец режима (около минуты:
запущенная лаба опрашивается раз в 15 с). Заглушка: `?maintenance=<секунды>` объявляет обслуживание при открытии,
`window.__stub.maintenance(секунды | null)` меняет его.

Блок «Что проверять» формы активности (`checksform.js`, `docs/autochecks.md` §12) — `node check_checksform.js [--min]`: страница
`checksform.<язык>.html` — голая форма с выбором лабы Moodle, скрытым полем `checksdef` и блоком; активность на проверках лабы
берёт их себе, правит скрипт, «Проверить у менеджера» (заглушка `validate_checks` отказывает скрипту на устройстве, которого
нет в выбранной версии), переход на версию без проверок переносит прежние в активность, «Вернуть проверки лабы» очищает поле;
`checksform.<язык>.own.html` — активность со своими проверками и окно промпта; `editor.<язык>.activitychecks.html` — редактор
лаб без блока проверок, черновик сохраняется без них. Заглушка помнит вызовы в `window.__stub.checksform`
(`labs`, `validated`, `down = true` — менеджер не отвечает).

Преднастрой преподавателя (`setupform.js`, `promptwindow.js`, `docs/lab-setup.md`) — `node check_setup.js [--min]`: сам поднимает
сервер на 18141 и mock-менеджер на 18142 (слот 18143; Python с aiohttp — `PYTHON`, по умолчанию `/tmp/gns-venv/bin/python`,
если есть). `editor.<язык>.setup.html` — менеджер с `lab-setup`, лаба с сегментом, ISP и одним шагом: промпт (`[[LAB]]` с видом
шага, оболочкой и адресами плана), ответ карточками с находками редактора, «Проверить у менеджера» (заглушка `validate_lab`
отказывает шагу на PC2 — «нет гостевого агента» — и помнит присланные шаги в `window.__stub.editor.setupValidated`),
«Заменить» / «Добавить», «Отменить», ручные поля и JSON; `editor.<язык>.setup-kept.html` — менеджер без `lab-setup`, шаги только
для чтения; `editor.<язык>.setup-authoring.html` и `authoring.<язык>.setup.html` — авторский запуск через mock-менеджер
(`POST /mock/setup/fail-next`): упавший шаг, «Промпт: исправить шаг» и окно в редакторе. `?setupfail` на странице лабы —
запуск падает с `SETUP_FAILED` (с `?observer` — со строкой шага, как её отдаёт сервер наблюдателю).

Перед приёмкой в dev-Moodle 5.1: пересобрать `grunt amd`, проверить права студента/наблюдателя,
описание активности с форматированием и файлами, реальные факты/консоли и сбросить кэши Moodle.
Harness не заменяет проверки PHP/Behat и работу с настоящим менеджером.

```bash
cd plugin/devtools/ui-harness
npm install
node build.js          # → dist/
node server.js         # → http://127.0.0.1:8123/index.ru.html
```

Страницы: `index.ru.html`, `index.en.html`, `index.viewer.html` (пользователь без права запуска); режимы схемы (`docs/lab-constructor/README.md`
§2) — `index.<язык>.seen.html`, `index.<язык>.fog.html` (все устройства силуэтами) и `index.<язык>.fog-start.html` (туман со стартовым
PC1); с `?observer` те же страницы открывает преподаватель: он видит всё и по кнопке «Как видит студент» — маску студента; лаба `linux-switch-vlan`
(Linux-коммутатор с VLAN и транком; «Обновить сейчас» выключает порт PC1) — `index.ru.linux-switch-vlan.html` и
`index.en.linux-switch-vlan.html`, остальные параметры те же. Параметры адреса:
`?fast` — лаба запускается за секунду, `?theme=dark`, `?min` — модули из `plugin/amd/build`, `?conflict` — старт отвечает
«уже есть другая лаба», `?observer` — чужая работающая лаба, только просмотр, `?nofacts` — сессия без фактов,
`?factsempty` — факты ещё не собраны (rev 0). В консоли браузера `window.__stub.setNode(<node_id>, 'stopped'|'started')` меняет состояние ноды. Живые факты — демо-фикстуры: «Обновить сейчас» переключает верный конфиг и конфиг с ошибками;
`window.__stub.calls` считает вызовы external functions (по имени), по нему видно, спрашивала ли страница факты;
`__stub.facts.fail(<node_id>, 'timeout')` — сбор с ноды не удался, `__stub.facts.stale(true)` — сбор встал давно,
`__stub.facts.fill()` / `empty()` — есть данные / нет данных. Опрос идёт раз в 30 с; событие `visibilitychange` на
`document` запрашивает факты сразу.

`node build.js --amd-build [--only=lab,stage]` пишет минифицированные модули и карты в `plugin/amd/build` — запасной
вариант на случай, когда `grunt amd` недоступен. Это не замена: перед выпуском пересоберите `grunt amd` в dev-Moodle
(ESLint Moodle, родная сборка), результат Babel и terser от неё отличается.

## Окно задания

Задание (описание активности) открывается кнопкой «Задание» плавающим окном в слое окон консолей (`amd/src/assignment.js`):
перетаскивается за заголовок, меняет размер за угол, сворачивается в заголовок кнопкой или двойным щелчком, щелчки по схеме
и карточка объекта его не закрывают. Положение, размер, свёрнутость и прокрутка запоминаются в браузере для каждой
активности (`localStorage`, ключ `gns3lab.assignment.<cmid>`). На телефоне это шторка над кнопками масштаба, касание заголовка
сворачивает её. Сквозная проверка — `node check_assignment.js [--min]`.

## Автопроверки

`index.<язык>.checks.html` — элемент с автопроверками (`docs/autochecks.md`): заглушки `mod_gns3lab_get_checks`, `_start_check`,
`_get_check_run`; прогон длится 2 с (`?fast` — 0,5 с), отчёт зависит от варианта фактов («Обновить сейчас» — конфиг с ошибками).
`?checksreport=counts|after` — сервер прячет находки, `?checksmax=N` — лимит попыток (0 — без ограничения), `?observer` — без кнопки.
`window.__stub.checks.next('incomplete'|'failed')` — исход следующего прогона. Сквозная проверка — `node check_checks.js [--min]`.
С `?checkteacher` в отчёте — скрипты преподавателя с выводом (`docs/autochecks.md` §9). Редактор лаб со скриптами —
`editor.<язык>.scripts.html` (проверка в `check_editor.js`).

## Графическая консоль (noVNC)

Нода с `console_type: vnc` (в демо-лабе — PVE1) открывается экраном. Шлюз харнесса для неё не отвечает сам, а пересылает
двоичные кадры (сырой поток RFB) в обе стороны поддельному слоту mock-менеджера (`HARNESS_SLOT_URL`, по умолчанию
`ws://127.0.0.1:8091`) и закрывает консоль кодом `4000` (слот закрылся) или `4001` (слот не пустил). Значит, для экрана
нужен запущенный `devtools/mock-manager/mock_manager.py` (`pip install aiohttp`); без него консоль PVE1 уходит в
«Консоль устройства недоступна». `GET /gw/stats` — сколько экранов открыто на шлюзе сейчас.

Сквозная проверка в Chromium — `check_vnc.js`: поднимает оба сервера на портах 18090, 18091 и 18123, ведёт страницу
(рабочий стол, телефон, преподаватель) и читает, что дошло до RFB-сервера, из `GET /mock/vnc/<node_id>`:

```bash
cd plugin/devtools/ui-harness
npm install
PYTHON=python3 node check_vnc.js --shots /tmp/vnc-shots   # нужен Playwright с Chromium (require('playwright'))
```

Каждая проверка печатается как `PASS` / `FAIL`, код выхода — число провалов; скриншоты (панель, меню язычка, полный экран,
сетка, окна, пауза переподключения, шторка телефона) — в каталоге `--shots` (по умолчанию `dist/shots`).

Полный экран (0.47.0): монитор контекста — 1536×864 CSS при `deviceScaleFactor` 1.25, значит, узел должен получить просьбу
1920×1080. Поддельный слот ведёт себя как QEMU 8.2 с virtio-gpu и гостем, который следует просьбе: объявляет
ExtendedDesktopSize на полный запрос кадра, на SetDesktopSize отвечает «передано» (статус 4) и сразу присылает новый размер
с картинкой; просьбы видны в `GET /mock/vnc/<node_id>` как события `resize`. Проверяются язычок и меню (нет «Вставить»),
размер для полного экрана (2K-предел), запрос 1920×1080, возврат к 320×200 при выходе и то, что запомненный размер стирается.

Страница преподавателя «Лабы курса» (`course.php`, `docs/teacher-dashboard.md`): `index.<язык>.course.html` — настоящий шаблон `course.mustache`
и модуль `course.js` против заглушки `mod_gns3lab_get_course_overview` (пять студентов, три лабы с оценками журнала и прогонами
проверок, две группы; у студентов 11 и 12 есть факты — верные и с ошибками). Открывается сводка, `&lab=<cmid>` — вкладка лабы. `?laberror` — менеджер не ответил
по второй лабе, `?coursefail` — вызов не удался, `?nogrades` — преподаватель без права видеть оценки. `window.__stub.course.set(cmid, userid, сводка|null)` меняет
ячейку, `.result(cmid, userid, оценка|null, проверки|null)` — её оценку и проверки, `.bump(userid)` двигает rev фактов. Сквозная проверка в Chromium —
`check_course.js` (сводка и итоги, вкладка лабы, цифры фактов, «без изменений N мин» на часах Playwright, поиск, сортировка, группа, карточка с оценкой и историей
проверок, адреса и «назад» браузера, телефон 360 px, ошибка по лабе, экранирование имён): `node check_course.js [--min] [--shots <каталог>]`.

Запрет вставки в консоль (поле ноды `nopaste` лабы библиотеки, `docs/SPEC.md` §5.1): `index.<язык>.nopaste.html` — помечены SW1
и нода с экраном VNC. Проверка — `node check_nopaste.js [--min]` (порт 18131, Playwright с Chromium): в консоли SW1 событие `paste`,
Ctrl+V, Ctrl+Shift+V, Shift+Insert, перетаскивание и ввод одним длинным куском до устройства не доходят, набор с клавиатуры и сниппет
доходят, у помеченного экрана нет кнопки «Вставить»; непомеченный R1 той же лабы и лаба без пометок вставку принимают. Галочку
в редакторе проверяет `check_editor.js`.

Одно место на лабу (`docs/seat.md`): `index.<язык>.seat.html` — активность в режиме «одна страница»; `?seat=othertab` и
`?seat=otherlogin` открывают её с местом, занятым другой страницей того же входа или другим входом; в консоли браузера
`window.__stub.seat.give('me'|'othertab'|'otherlogin')` передаёт место, `__stub.seat.claims` и `.gated` показывают, что и с каким
id страницы страница спрашивала. Сквозная проверка — `check_seat.js` (порт 18127, Playwright с Chromium; `--min` — минифицированные
модули): стена для другого входа и для другой вкладки, кнопка «Работать с лабой здесь», закрытие консолей, телефон, русский текст.

```bash
cd plugin/devtools/ui-harness
node check_seat.js [--min] [--shots /tmp/seat-shots]
```

Проверка слоя «увидено в консоли» — `check_seen.js`: поднимает только шлюз харнесса (порт 18124), в Chromium запускает
лабу, набирает в консолях SW1 и PC1 `sh int status`, `sh vl br`, `show ip`, `wr` и проверяет, что схема меняется сразу, без
опроса фактов (кабель к PC2 гаснет, адрес PC1 на L3 меняется), что карточка узла подписана и поля отмечены, что `write` с `[OK]`
просит свежие факты не чаще раза в 10 с и что новый снимок сбрасывает увиденное на SW1, но не на PC1. `--min` — те же
проверки на минифицированных модулях `amd/build`.

```bash
cd plugin/devtools/ui-harness
npm install
node check_seen.js [--min] [--shots /tmp/seen-shots]    # нужен Playwright с Chromium; mock-менеджер не нужен
```

## Авторский запуск и производные образы

`editor.ru.authoring.html` / `editor.en.authoring.html` открывают настоящий редактор
с capture, `authoring.<язык>.html` — существующий интерфейс сессии и консолей с
авторским транспортом. `server.js` играет только Moodle-посредника: права и
конкурентные правки БД проверяются в dev-Moodle, не в Node-заглушке. API снятия,
задержка, сбой, каталог и PATCH — у настоящего `devtools/mock-manager`.

В трёх терминалах (из корня репозитория; Python с зависимостями проекта):

```sh
MOCK_PORT=18090 MOCK_SLOT_PORT=18091 GW_INTERNAL_URL=http://127.0.0.1:18080 \
  GW_PUBLIC_URL=ws://127.0.0.1:18080 MOCK_CAPTURE_DELAY=0.1 \
  python3 plugin/devtools/mock-manager/mock_manager.py

GW_PORT=18080 GW_SLOT_PORT=18091 GW_SLOT_SCHEME=ws GW_ALLOW_PLAINTEXT_SLOTS=1 \
  GW_INTERNAL_KEY=dev-internal-key GW_ALLOWED_ORIGINS=http://127.0.0.1:18123 \
  GW_SLOTS='{"127.0.0.1":"dev-console-token"}' python3 manager/gateway/console_gateway.py

cd plugin/devtools/ui-harness
npm install
node build.js
node server.js 18123
```

Проверка: `node check_derived.js [--min]` (Playwright; `CHROMIUM_BIN` — путь к Chromium,
по умолчанию `/usr/lib/chromium/chromium`; `SHOTS` — каталог скриншотов).
Она проверяет настоящую консоль mock-слота через шлюз, список снимаемых нод,
успех, отсутствие частичного каталога при сбое, повтор, `supersedes`, featured,
экранирование, поиск и мобильную страницу. Проверяются также `poweroff` в терминале
(авторская сессия падает с SLOT_LAB_FAILED), повторный запуск, успешный shutdown
слота, частичный сбой quiesce с живой сессией, повтор,
явное сохранение как есть, предупреждение у образа и снятие из остановленной сессии.
Это не проверка GNS3/QEMU/CephFS.
`MOCK_CAPTURE_FAIL=1` или `POST /mock/capture-fail/on` включает сбой;
`POST /mock/capture-fail/off` выключает. `MOCK_CAPTURE_DELAY` — секунды до снятия
после остановки. `POST /mock/shutdown-fail` с JSON
`{"nodes":{"PC2":"GUEST_AGENT_UNAVAILABLE"},"supported":true}` задаёт сбой
выключения; `{"nodes":{},"supported":true}` возвращает успех.
`supported: false` имитирует слот без возможности `guest-shutdown`.
Эти средства предназначены только для локальной разработки.
