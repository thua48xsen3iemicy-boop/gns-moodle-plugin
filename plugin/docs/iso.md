# «Смонтировать ISO» (0.34.0)

Студент кладёт файлы в оговорённый каталог ноды-источника, открывает колесо действий этой ноды и нажимает «ISO».
Слот собирает из каталога ISO-образ и вставляет его в CD-привод всех нод-приёмников лабы, кроме самого источника.
Контракт — `manager/docs/CONTRACTS.md` §2.12 (плагин ↔ менеджер) и §4.7 (менеджер ↔ слот).

- Какие образы — источники и приёмники, решает администратор в каталоге образов менеджера (`iso_source` — путь каталога в
  госте, `iso_target: true`). Плагин путь не видит: сессия несёт только `iso.sources` и `iso.targets`
  (`session_data::iso_nodes`, поля `isosources`/`isotargets` в `get_state`).
- `mod_gns3lab_start_iso` (write) — только своя запущенная лаба и только нода из `isosources`, со `tabid` (одно место на лабу,
  `docs/seat.md`). Наблюдатель кнопку не видит, а вызвать её для чужой лабы нельзя: у функции нет `userid`.
- `mod_gns3lab_get_iso` (read) — состояние операции; страница опрашивает раз в 1,5 с и показывает итог всплывающим
  сообщением: куда подключён образ или почему не собрался (`ui_iso_err_*`).
- В Linux-приёмнике смонтированный `/dev/sr0` после новой сборки нужно перемонтировать: `mount /dev/sr0 /mnt`. Windows видит
  новый диск сама.

Проверка без Moodle — `devtools/ui-harness/check_iso.js`; mock-менеджер объявляет все QEMU-ноды лабы источниками и приёмниками
(`POST /mock/iso/next` проваливает следующую сборку).
