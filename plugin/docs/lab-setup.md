# Преднастрой преподавателя в плагине (0.51.0)

Проект — `../../docs/lab-setup/README.md` (§4 формат, §6 сбой, §6a интерфейс, §9 «Плагин (этап 1)»), контракт —
`manager/docs/CONTRACTS.md` §2.6 «Преднастрой преподавателя», §2.3 `setup_error`, §2.5 `SETUP_FAILED`, возможность
`lab-setup` (менеджер 0.40.0). Здесь — как это устроено в плагине.

## 1. Определение лабы

- Поле `setup` в `gns3lab.lab/2` — список шагов `{"id", "title", "node", "run" | "config", "shell"?, "timeout"?}`.
  `lab_definition::from_json` проверяет только форму: список объектов, весь JSON до `SETUP_MAX` (64 КБ). Поля, пределы,
  ноды и оболочки проверяет менеджер (`validate`). Пустой список — нет поля.
- Лаба с шагами — `lab/2`; без сегментов — с `"segments": []` (как у проверок). `for_manager` отдаёт `setup` как есть,
  пустой шаг уходит объектом (`setup_objects`), чтобы менеджер ответил `required`, а не `bad_type`.
- `without_checks` (публикация при `activity-checks`) шаги не трогает: они часть лабы. Лаба только с шагами остаётся `lab/2`.
- `manager_client::supports_lab_setup()` — `lab_constructor` (с `lab/2`) и `lab-setup`.

## 2. Редактор лаб: блок «Преднастрой»

Блок в панели лабы (ничего не выделено), между сегментами и проверками: `amd/src/setupform.js` (`create`), окно промпта —
`amd/src/promptwindow.js` (общее с блоком проверок `checksform.js`).

- Главные кнопки — «Промпт для нейросети» и «Вставить ответ» (вкладки одного окна). Промпт — `prompts/setup.<язык>.md`
  без ведущих HTML-комментариев (`classes/local/setup_prompt.php`, читает так же, как `checks_prompt.php`), подстановки:
  - `[[LAB]]` — JSON: устройства (`name`, `image`, `kind`, `category`, `step`: `run` | `config` | `null`, у `run` — `shell`
    `sh` или `routeros` и `os`), линии портами (`["SW1 Ethernet0", "PC1 Ethernet0"]`), сегменты с адресами плана
    (`segments.js` `plan`: `subnet`, `vlan`, `configure`, шлюз и участники портами с `ip`/префиксом);
  - `[[SETUP]]` — `{"setup": [...]}` лабы или «шагов пока нет»; `[[TASK]]` — задача преподавателя.
  Задача и ответ живут, пока открыт редактор.
- Ответ — `{"setup": [...]}`, голый список или то же в блоке ` ```json `. Карточки шагов: название, `id`, устройство, образ,
  оболочка и время или «строки конфигурации», код. Сразу — что видит редактор (`problemsOf`): устройства нет, на нём шаги не
  выполняются (ISP, коммутатор GNS3, неизвестный вид), поле не для вида (`run` у IOL/VPCS, `config`/`shell`/`timeout` у
  QEMU), нет `run`/`config`, неверный или повторный `id`, название, `run` длиннее 8000 байт, оболочка не та (по
  `guest: "routeros"` каталога), время вне 1…120, не ASCII в `config`, больше 30 шагов, сумма времени больше 600 с.
- «Проверить у менеджера» — `mod_gns3lab_validate_lab` с лабой, где ответ — весь преднастрой; находки с путём
  `setup[i]…` ложатся на карточку `i`, остальные — общим списком. Код `setup_node_unsupported` — своей строкой
  (`ed_problem_setup_node_unsupported`), незнакомый код — как есть.
- «Заменить преднастрой» и «Добавить к имеющимся» — одна правка редактора («Отменить», Ctrl+Z). «Добавить» недоступно,
  пока `id` ответа совпадают с имеющимися.
- Под карточками свёрнуты «Править шаги вручную» (устройство, название, `id`; у QEMU — скрипт, оболочка, время; у IOL/VPCS —
  строки конфигурации; выше/ниже, удалить, добавить) и «Преднастрой в JSON». Неверный JSON — сообщение под блоком.
- «Проверить» всей лабы показывает находки шагов в общем списке как «Преднастрой · <шаг> · <поле>» и на карточке шага.
- Без `lab-setup` у менеджера шаги черновика видны карточками только для чтения и остаются в определении.

## 3. Сбой шага (`SETUP_FAILED`)

- `session_data::export($session, $setupdetail)` добавляет `setuperror` `{step, node, exitcode, message}` только когда
  сессия `failed` с `SETUP_FAILED` и у неё есть `setup_error`, и только если так решил вызывающий: `get_state` — при
  `mod/gns3lab:observe` в элементе, `mod_gns3lab_authoring` — всегда (автор лабы). `start_session` и `stop_session` его
  не отдают. Студент получает только код.
- `session.js`: `SETUP_FAILED` — «Лаба не подготовилась: ошибка в преднастрое лабы. Сообщите преподавателю.» без «Запустить
  снова»; при `setuperror` — строка «Шаг преднастроя «web» на SRV1 вышел с кодом 100: …» (только текстом,
  `data-region="setuperror"`).
- Авторский запуск (`authoring.php` передаёт `labsetup`): кнопка «Промпт: исправить шаг» (`lab.js` `renderSetupFix`). Окно
  открывается в редакторе лабы: страница в окне редактора шлёт `postMessage` родителю, открытая отдельной вкладкой —
  `BroadcastChannel("gns3lab-editor-<labid>")`; редактор отвечает `gns3lab-setup-fix-ack`, без ответа страница говорит
  «откройте редактор этой лабы». В задаче — шаг, нода, код, строка ошибки и код шага; ответ заменяет только этот шаг
  (`id` из ответа, иначе единственный шаг ответа) одной правкой редактора.

## 4. Проверки активности

`checks_lab::context` отдаёт `setup` — шаги выбранной версии без кода (`id`, `title`, `node`); `get_checks_lab` — поле
`setup`; `checksform.js` кладёт в `[[LAB]]` промпта проверок `"setup": [{"title", "node"}]`. Редактор лаб без
`activity-checks` делает то же для промпта проверок лабы.

## 5. Проверки

- Браузер: `devtools/ui-harness/check_setup.js [--min]` (страницы `editor.<язык>.setup.html`, `.setup-kept.html`,
  `.setup-authoring.html`, `authoring.<язык>.setup.html`, `index.<язык>.html?setupfail[&observer]`; нужен mock-менеджер с
  aiohttp). Окно промпта проверок — прежние `check_editor.js`, `check_checksform.js`.
- Mock-менеджер: `lab-setup`, `lab/2` с `setup`, `POST /mock/setup/fail-next` (докстрока `mock_manager.py`).
- PHPUnit: `tests/external/lab_setup_test.php`.

## 6. Что проверить на стенде

1. Менеджер 0.40.0+ и плагин 0.51.0, сброс кэшей Moodle. В редакторе лабы — блок «Преднастрой» с кнопками промпта.
2. Путь §12 п. 1 проекта: промпт → нейросеть → «Вставить ответ» → карточки → «Проверить у менеджера» → «Заменить
   преднастрой» → «Опубликовать»; авторский запуск выполняет шаги.
3. Шаг `exit 3`: авторский запуск — строка шага и «Промпт: исправить шаг», окно в редакторе с кодом и ошибкой, ответ
   заменяет только этот шаг; страница студента — общий текст, наблюдатель — строка шага без кнопки.
4. Образ без гостевого агента (`qga: false`): шаг на нём — находка менеджера на карточке.
5. Промпт проверок в форме активности на версии с шагами — в `[[LAB]]` есть `setup` с названиями, без кода.
