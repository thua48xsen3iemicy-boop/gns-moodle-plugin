# Лабы курса: страница преподавателя

Задание исполнителю (плагин `mod_gns3lab`, версия 0.14.0). Пути — относительно `plugin/`.
Перед работой прочитай `AGENTS.md`, `docs/SPEC.md` (§5.2, §5.3, §5.4) и `docs/live-state.md` §1–4.

## 1. Зачем и решения владельца

Преподаватель на занятии смотрит, кто из студентов как продвигается: у кого лаба запущена, у кого
застряла, где на схеме ошибки. Решения владельца:

- **Своя страница, без отчётов Moodle.** Таблицы оценок, конструктор отчётов и обзор активностей не
  используем. От Moodle остаются только вход, права, группы, external functions, MUC, языковые строки
  и переменные темы Boost (тёмную тему не ломать). Раскладка страницы как у `lab.php`: `embedded`, свой шаблон, свой AMD-модуль.
- **Одна страница на курс.** На ней все лабы этого курса, которые преподаватель может наблюдать.
- **Сейчас только факты.** История попыток и проверок появится вместе с проверками (`checks`
  у менеджера). Сейчас для неё только место в карточке студента, без данных и без запросов (§5.3).
- **Не делаем:** остановку лабы преподавателем, кнопку «Нужна помощь», правку контракта с менеджером.
  Все данные берутся из существующих маршрутов (`manager/docs/CONTRACTS.md` §2.4, §2.7).

## 2. Вход на страницу

- Адрес `mod/gns3lab/course.php?id=<courseid>`.
- Пункт «Лабы курса» в навигации курса (`gns3lab_extend_navigation_course` в `lib.php`; в Moodle 5.1
  он попадает в меню «Ещё» вторичной навигации). Показывается, только если в курсе есть хотя бы одна
  активность `gns3lab`, видимая пользователю (`cm->uservisible`), и в одной из них у него есть
  `mod/gns3lab:observe`. Список берётся из `get_fast_modinfo($course)`, без запросов к менеджеру.
- Ссылка «Лабы курса» на `view.php` рядом с «Открыть лабу». Видна только при `observe`.
- `course.php`: `require_login($course)`. Лабы страницы — видимые активности курса с `observe`
  в контексте модуля. Если таких нет, страница отказывает (`nopermissions`), студент её не откроет и подстановкой адреса.
- Наверху своя шапка: название курса, ссылка назад в курс, выбор группы, время последнего обновления.

## 3. Кто в таблице

- Студент — пользователь с `mod/gns3lab:use` в контексте лабы без `mod/gns3lab:observe` (преподаватели,
  у которых тоже есть `use`, в строки не попадают). Строки — объединение студентов всех лаб страницы.
- Группы: выбор группы на странице — группы курса, которые преподаватель может видеть
  (все при `moodle/site:accessallgroups`, иначе свои). Ячейку «студент × лаба» сервер отдаёт, только если
  `lab_access::can_observe_user()` для этой лабы истинно (у лаб может быть свой режим групп). Иначе ячейка
  `observable: false` и рисуется прочерком.
- Имя — `fullname()`, аватар — `user_picture` маленького размера. Других данных профиля не отдавать.

## 4. Данные

### 4.1. Новая external function `mod_gns3lab_get_course_overview`

`courseid`, `groupid=0` → таблица. Проверки: `validate_context` курса, затем для каждой лабы `observe`
(лабы без права просто не попадают в ответ; если не осталось ни одной — отказ). `ajax => true`, `loginrequired => true`, не меняет данные.

Структура ответа (строго через `external_*_structure`):

```
labs:     [{cmid, name, error}]          error — код, если менеджер не ответил по этой лабе, иначе пусто
students: [{userid, fullname, pictureurl}]
cells:    [{cmid, userid, observable, session}]
```

`session` — сводка без топологии или `null`, если сессий не было: `status`, время начала, время
окончания (если менеджер его даёт), признак `facts` в `features` (если его нет в списке — узнаётся при
открытии карточки). Набор полей — из ответа `GET /api/v1/sessions?instance_id=` (CONTRACTS §2.4, §2.3),
id сессии в браузер не отдавать. Источник — `manager_client::list_activity_sessions()` по каждой лабе
страницы. Ответ менеджера кэшировать новым определением MUC `activitysessions` (ключ — id активности,
свежесть 10 с), чтобы несколько преподавателей и опрос раз в 15 с не умножали запросы. Менеджер недоступен
по одной лабе — у неё `error`, остальные лабы отдаются.

### 4.2. Факты студента — существующие вызовы

`mod_gns3lab_get_state` и `mod_gns3lab_get_facts` уже принимают `userid` и проверяют `observe` и группы.
Новых вызовов для фактов не нужно. Сводку из фактов считает браузер теми же функциями, что и страница
лабы: `model.buildModel()` по топологии из `get_state`, затем `facts.derive()`; находки — `issues` слоёв
`l1`, `l2`, `l3`, `rt` с важностью `bad` / `warn` / `info`. В PHP логику слоёв не повторять.

Расчёт — в отдельном модуле без DOM `amd/src/coursefacts.js`: по модели и документу фактов
возвращает сводку ячейки (§5.2) и данные карточки (§5.3). Проверка без браузера — `devtools/check_coursefacts.mjs`
по фикстурам (`fixtures/`, `docs/live-state.md` §5), как `devtools/check_reveal.mjs`.

### 4.3. Нагрузка

- Таблица опрашивает `get_course_overview` раз в 15 с, пока страница видна (`visibilitychange`).
- Факты в таблице — только для запущенных сессий с `facts`. Топология (`get_state`) берётся один раз на
  сессию и при смене её статуса, дальше только `get_facts` с `sincerev` раз в 60 с. Не больше 4 запросов
  одновременно. Кэш фактов `session_facts` на сервере уже есть.
- Открытая карточка опрашивает свои факты как страница лабы (30 с, 3 с при `iol.l1/1`).
- Если на стенде этого окажется много — сначала измерить, потом предлагать сводный вызов. Контракт не трогать.

## 5. Интерфейс

Корень стилей — `.gns3lab-course`, стили в `styles.css`, только переменные темы. Ванильный JS, AMD-модуль
`amd/src/course.js`, шаблон `templates/course.mustache`. Все строки — `lang/en` и `lang/ru`.

### 5.1. Таблица «студенты × лабы»

- Строки — студенты, столбцы — лабы в порядке курса. Закреплённые первый столбец и шапка, горизонтальная
  прокрутка внутри таблицы. Поиск по имени, сортировка по имени и по состоянию в выбранной лабе.
- Ячейка: состояние (не начинал, запускается, работает, останавливается, остановлена, ошибка), у
  запущенной — сколько осталось или сколько идёт.
- Над таблицей — счётчики по лабе: «работают N, ошибка M, не начинали K».
- Ошибка менеджера по лабе — пометка в шапке столбца, а не пустые ячейки без объяснения.

### 5.2. Сводка фактов в ячейке

У запущенной сессии с фактами:
- число находок `bad` и `warn` по всем слоям (цвет ячейки по худшей);
- «без изменений N мин» — время с последней смены `rev` фактов, которую видела страница. Это признак «застрял»;
  считается в браузере с момента открытия страницы, до первой смены пишется «нет изменений с HH:MM»;
- факты устарели или недоступны — серый значок с подсказкой, а не «всё хорошо» (live-state.md §1: неизвестно ≠ выключено).

### 5.3. Карточка «студент × лаба»

Открывается щелчком по ячейке: боковая панель на широком экране, отдельный экран на телефоне. Адрес страницы
меняется (`#cm=<cmid>&user=<userid>`), чтобы карточку можно было обновить и вернуться назад.

1. Шапка: студент, лаба, состояние сессии и время, кнопка «Открыть схему» → `lab.php?id=<cmid>&userid=<userid>`
   (режим наблюдателя, §6).
2. Находки по слоям L1 / L2 / L3 / маршрутизация — тексты `issues` из `derive()`, важные первыми.
3. Устройства: имя, запущено ли, интерфейсы (сколько подняты из скольких), адреса IPv4. Только из фактов и
   топологии, без консолей.
4. «История попыток и проверок» — заголовок и строка «Появится вместе с автоматическими проверками». Без
   запросов. Разметку сделать так, чтобы список записей потом вставился без переделки карточки.

Нет сессии — карточка показывает «Студент ещё не запускал лабу» и тот же блок истории.

### 5.4. Телефон

Ширина 360 px: таблица прокручивается, карточка на весь экран, кнопка назад к таблице. Сенсорные цели не меньше 40 px.

## 6. `lab.php` для наблюдателя

`lab.js` уже принимает `userid` и работает в режиме только чтения (`readonly`, схема `live`), но `lab.php`
этот параметр не передаёт. Добавить `userid` (`optional_param`, по умолчанию 0): чужой `userid` — проверка
`lab_access::resolve_user()` до вывода страницы, затем `lab.init(..., userid)` из шаблона. В шапке — имя
студента, бейдж «Только просмотр» и ссылка назад на `course.php` (если пришли оттуда). Место (`seat`) наблюдатель не занимает — так уже сделано.

## 8. Проверки

- PHPUnit на `get_course_overview`: студент получает отказ; преподаватель без `accessallgroups` видит
  только студентов своих групп, ячейки чужих групп `observable: false`; лаба без `observe` не попадает
  в ответ; преподаватели не попадают в строки; недоступный менеджер по одной лабе даёт `error` только у неё;
  id сессии в ответе нет.
- PHPUnit на `lab.php`/`resolve_user` не нужен, если уже покрыт тестами external functions, — проверь и напиши, чем покрыт.
- `devtools/check_coursefacts.mjs` — сводка по фикстуре с ошибками и по документу без фактов.
- `php -l` всех изменённых PHP; phpcs, PHPUnit, `grunt amd` — в dev-Moodle (`AGENTS.md`).
- Mock-менеджер (`devtools/`): если он не отдаёт `GET /api/v1/sessions?instance_id=`, добавить, чтобы страницу можно было посмотреть без стенда.

## 9. Проверка на стенде (владелец)

1. Курс с двумя лабами и двумя группами; преподаватель без `accessallgroups` в одной группе, три студента.
2. Пункт «Лабы курса» виден преподавателю и не виден студенту; прямой адрес студенту отказывает.
3. Два студента запускают лабы: в таблице «работает», через 15 с без перезагрузки. Студент чужой группы — прочерк.
4. Студент ломает адрес на интерфейсе: в течение минуты в ячейке растёт число `bad`, в карточке — текст находки.
5. «Открыть схему» открывает лабу студента только для чтения; ввод в консоли не проходит.
6. Менеджер остановлен: страница открывается, у лаб пометка ошибки, без трассировки.
7. Телефон: таблица прокручивается, карточка открывается и закрывается кнопкой назад.
