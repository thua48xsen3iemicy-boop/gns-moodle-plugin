# Лабы курса: страница преподавателя

Задание исполнителю (плагин `mod_gns3lab`, версия 0.14.0). Пути — относительно `plugin/`.
С 0.28.0 страница состоит из сводки оценок и вида одной лабы: см. §12. Там, где §5 и §12 расходятся, действует §12.
Перед работой прочитай `AGENTS.md`, `docs/SPEC.md` (§5.2, §5.3, §5.4) и `docs/live-state.md` §1–4.

## 1. Зачем и решения владельца

Преподаватель на занятии смотрит, кто из студентов как продвигается: у кого лаба запущена, у кого
застряла, где на схеме ошибки. Решения владельца:

- **Своя страница, без отчётов Moodle.** Таблицы оценок, конструктор отчётов и обзор активностей не
  используем. От Moodle остаются только вход, права, группы, external functions, MUC, языковые строки
  и переменные темы Boost (тёмную тему не ломать). Раскладка страницы как у `lab.php`: `embedded`, свой шаблон, свой AMD-модуль.
- **Одна страница на курс.** На ней все лабы этого курса, которые преподаватель может наблюдать.
- **Сейчас только факты.** История попыток и проверок появится вместе с проверками (`checks`
  у менеджера). Сейчас для неё только место в карточке студента, без данных и без запросов (§5.3).
- **Не делаем:** остановку лабы преподавателем, кнопку «Нужна помощь», правку контракта с менеджером.
  Все данные берутся из существующих маршрутов (`manager/docs/CONTRACTS.md` §2.4, §2.7).

## 2. Вход на страницу

- Адрес `mod/gns3lab/course.php?id=<courseid>`.
- Пункт «Лабы курса» в навигации курса (`gns3lab_extend_navigation_course` в `lib.php`; в Moodle 5.1
  он попадает в меню «Ещё» вторичной навигации). Показывается, только если в курсе есть хотя бы одна
  активность `gns3lab`, видимая пользователю (`cm->uservisible`), и в одной из них у него есть
  `mod/gns3lab:observe`. Список берётся из `get_fast_modinfo($course)`, без запросов к менеджеру.
- Ссылка «Лабы курса» на `view.php` рядом с «Открыть лабу». Видна только при `observe`.
- `course.php`: `require_login($course)`. Лабы страницы — видимые активности курса с `observe`
  в контексте модуля. Если таких нет, страница отказывает (`nopermissions`), студент её не откроет и подстановкой адреса.
- Наверху своя шапка: название курса, ссылка назад в курс, выбор группы, время последнего обновления.

## 3. Кто в таблице

- Студент — пользователь с `mod/gns3lab:use` в контексте лабы без `mod/gns3lab:observe` (преподаватели,
  у которых тоже есть `use`, в строки не попадают). Строки — объединение студентов всех лаб страницы.
- Группы: выбор группы на странице — группы курса, которые преподаватель может видеть
  (все при `moodle/site:accessallgroups`, иначе свои). Ячейку «студент × лаба» сервер отдаёт, только если
  `lab_access::can_observe_user()` для этой лабы истинно (у лаб может быть свой режим групп). Иначе ячейка
  `observable: false` и рисуется прочерком.
- Имя — `fullname()`, аватар — `user_picture` маленького размера. Других данных профиля не отдавать.

## 4. Данные

### 4.1. Новая external function `mod_gns3lab_get_course_overview`

`courseid`, `groupid=0` → таблица. Проверки: `validate_context` курса, затем для каждой лабы `observe`
(лабы без права просто не попадают в ответ; если не осталось ни одной — отказ). `ajax => true`, `loginrequired => true`, не меняет данные.

Структура ответа (строго через `external_*_structure`):

```
labs:     [{cmid, name, error}]          error — код, если менеджер не ответил по этой лабе, иначе пусто
students: [{userid, fullname, pictureurl}]
cells:    [{cmid, userid, observable, session}]
```

`session` — сводка без топологии или `null`, если сессий не было: `status`, время начала, время
окончания (если менеджер его даёт), признак `facts` в `features` (если его нет в списке — узнаётся при
открытии карточки). Набор полей — из ответа `GET /api/v1/sessions?instance_id=` (CONTRACTS §2.4, §2.3),
id сессии в браузер не отдавать. Источник — `manager_client::list_activity_sessions()` по каждой лабе
страницы. Ответ менеджера кэшировать новым определением MUC `activitysessions` (ключ — id активности,
свежесть 10 с), чтобы несколько преподавателей и опрос раз в 15 с не умножали запросы. Менеджер недоступен
по одной лабе — у неё `error`, остальные лабы отдаются.

### 4.2. Факты студента — существующие вызовы

`mod_gns3lab_get_state` и `mod_gns3lab_get_facts` уже принимают `userid` и проверяют `observe` и группы.
Новых вызовов для фактов не нужно. Сводку из фактов считает браузер теми же функциями, что и страница
лабы: `model.buildModel()` по топологии из `get_state`, затем `facts.derive()`; находки — `issues` слоёв
`l1`, `l2`, `l3`, `rt` с важностью `bad` / `warn` / `info`. В PHP логику слоёв не повторять.

Расчёт — в отдельном модуле без DOM `amd/src/coursefacts.js`: по модели и документу фактов
возвращает сводку ячейки (§5.2) и данные карточки (§5.3). Проверка без браузера — `devtools/check_coursefacts.mjs`
по фикстурам (`fixtures/`, `docs/live-state.md` §5), как `devtools/check_reveal.mjs`.

### 4.3. Нагрузка

- Таблица опрашивает `get_course_overview` раз в 15 с, пока страница видна (`visibilitychange`).
- Факты в таблице — только для запущенных сессий с `facts`. Топология (`get_state`) берётся один раз на
  сессию и при смене её статуса, дальше только `get_facts` с `sincerev` раз в 60 с. Не больше 4 запросов
  одновременно. Кэш фактов `session_facts` на сервере уже есть.
- Открытая карточка опрашивает свои факты как страница лабы (30 с, 3 с при `iol.l1/1`).
- Если на стенде этого окажется много — сначала измерить, потом предлагать сводный вызов. Контракт не трогать.

## 5. Интерфейс

Корень стилей — `.gns3lab-course`, стили в `styles.css`, только переменные темы. Ванильный JS, AMD-модуль
`amd/src/course.js`, шаблон `templates/course.mustache`. Все строки — `lang/en` и `lang/ru`.

### 5.1. Таблица «студенты × лабы»

- Строки — студенты, столбцы — лабы в порядке курса. Закреплённые первый столбец и шапка, горизонтальная
  прокрутка внутри таблицы. Поиск по имени, сортировка по имени и по состоянию в выбранной лабе.
- Ячейка: состояние (не начинал, запускается, работает, останавливается, остановлена, ошибка), у
  запущенной — сколько осталось или сколько идёт.
- Над таблицей — счётчики по лабе: «работают N, ошибка M, не начинали K».
- Ошибка менеджера по лабе — пометка в шапке столбца, а не пустые ячейки без объяснения.

### 5.2. Сводка фактов в ячейке

У запущенной сессии с фактами:
- число находок `bad` и `warn` по всем слоям (цвет ячейки по худшей);
- «без изменений N мин» — время с последней смены `rev` фактов, которую видела страница. Это признак «застрял»;
  считается в браузере с момента открытия страницы, до первой смены пишется «нет изменений с HH:MM»;
- факты устарели или недоступны — серый значок с подсказкой, а не «всё хорошо» (live-state.md §1: неизвестно ≠ выключено).

### 5.3. Карточка «студент × лаба»

Открывается щелчком по ячейке: боковая панель на широком экране, отдельный экран на телефоне. Адрес страницы
меняется (`#cm=<cmid>&user=<userid>`), чтобы карточку можно было обновить и вернуться назад.

1. Шапка: студент, лаба, состояние сессии и время, кнопка «Открыть схему» → `lab.php?id=<cmid>&userid=<userid>`
   (режим наблюдателя, §6).
2. Находки по слоям L1 / L2 / L3 / маршрутизация — тексты `issues` из `derive()`, важные первыми.
3. Устройства: имя, запущено ли, интерфейсы (сколько подняты из скольких), адреса IPv4. Только из фактов и
   топологии, без консолей.
4. «История попыток и проверок» — заголовок и строка «Появится вместе с автоматическими проверками». Без
   запросов. Разметку сделать так, чтобы список записей потом вставился без переделки карточки.

Нет сессии — карточка показывает «Студент ещё не запускал лабу» и тот же блок истории.

### 5.4. Телефон

Ширина 360 px: таблица прокручивается, карточка на весь экран, кнопка назад к таблице. Сенсорные цели не меньше 40 px.

## 6. `lab.php` для наблюдателя

`lab.js` уже принимает `userid` и работает в режиме только чтения (`readonly`, схема `live`), но `lab.php`
этот параметр не передаёт. Добавить `userid` (`optional_param`, по умолчанию 0): чужой `userid` — проверка
`lab_access::resolve_user()` до вывода страницы, затем `lab.init(..., userid)` из шаблона. В шапке — имя
студента, бейдж «Только просмотр» и ссылка назад на `course.php` (если пришли оттуда). Место (`seat`) наблюдатель не занимает — так уже сделано.

## 9. Проверка на стенде (владелец)

1. Курс с двумя лабами и двумя группами; преподаватель без `accessallgroups` в одной группе, три студента.
2. Пункт «Лабы курса» виден преподавателю и не виден студенту; прямой адрес студенту отказывает.
3. Два студента запускают лабы: в таблице «работает», через 15 с без перезагрузки. Студент чужой группы — прочерк.
4. Студент ломает адрес на интерфейсе: в течение минуты в ячейке растёт число `bad`, в карточке — текст находки.
5. «Открыть схему» открывает лабу студента только для чтения; ввод в консоли не проходит.
6. Менеджер остановлен: страница открывается, у лаб пометка ошибки, без трассировки.
7. Телефон: таблица прокручивается, карточка открывается и закрывается кнопкой назад.

## 11. Как сделано в 0.14.0

**Страница и вход (§2, §6, §7).**
- `course.php?id=` — `require_login($course)`, затем `course_labs::has_observable()`: нет ни одной видимой лабы с `observe` — `nopermissions`.
  `classes/output/course_overview.php` и `templates/course.mustache` — рамка (шапка, группа, поиск, место таблицы и карточки);
  таблицу и карточку рисует `amd/src/course.js` только через `textContent` (имена и тексты находок как текст, не разметка).
- `classes/local/course_labs.php` — общее для страницы, навигации и вызова: `observable()` (лабы курса в порядке разделов, `uservisible`,
  `observe`), `groups()` (все при `accessallgroups`, иначе свои), `students()` (`use` без `observe` в контексте лабы, при желании только группа).
- Группы ячеек: `lab_access::share_group()` проверяет всех студентов лабы одним запросом участников групп преподавателя
  (`groups_get_groups_members`); `is_enrolled` для них не повторяется — `students()` уже взял только тех, у кого есть `use`.
  `can_observe_user()` для одного студента идёт через то же правило.
- Навигация: `gns3lab_extend_navigation_course` в `lib.php` (пункт «Лабы курса», без запросов к менеджеру); `overview.php` и `overview.mustache` —
  кнопка «Лабы курса» рядом с «Открыть лабу» при `observe`.
- `lab.php?id=&userid=&from=course`: чужой `userid` проходит `lab_access::resolve_user()` до вывода страницы (`observe`, группы, студент может
  пользоваться лабой; иначе `cannotobserveuser`), свой `userid` приравнен к 0. `viewer` получает `observing`, `studentname`, `userid`;
  в шапке — бейдж «Только просмотр» и имя студента; стрелка «назад» ведёт на `course.php`, если пришли оттуда (`from=course`; параметр
  добавлен к адресу из §5.3, чтобы «назад» знало откуда). Панель сессии у наблюдателя есть (она же опрашивает состояние), без кнопок:
  `get_state` отдаёт ему `canuse=false`. Место (`seat`) наблюдатель не занимает, как и раньше.
- `lab.js` и остальные модули страницы лабы не менялись: `userid` они уже принимали.

**Данные (§4).**
- `mod_gns3lab_get_course_overview(courseid, groupid)` — `classes/external/get_course_overview.php`, `db/services.php`. Ответ ровно по §4.1; `session`
  — `session_data::summary()`: `status`, `startedat`, `expiresat`, `facts` (`yes` / `no` / `unknown`), id сессии и топология не отдаются.
  Список сессий лабы — `activity_sessions::get()` через `manager_client::list_activity_sessions()`, кэш MUC `activitysessions` (`db/caches.php`),
  свежесть 10 с; недоступный менеджер (или не настроенный) даёт `error` только у лабы. Список сессий менеджера не несёт `features`
  (CONTRACTS §2.4), поэтому `facts` почти всегда `unknown`: страница узнаёт это по `get_state` (`features`) и `get_facts` (`available`).
- Строки таблицы: студент попадает в ответ, только если преподаватель может наблюдать его **хотя бы в одной** лабе страницы; в остальных
  лабах его ячейка `observable: false` (прочерк). Студент, которого нельзя наблюдать нигде, не приходит вовсе — без имени (см. «Решения»).
- Факты — существующие `get_state` / `get_facts` с `userid`; цифры считает `amd/src/coursefacts.js` (`summarize`, `card`, `trackRev`, `idleSince`).
  Нагрузка по §4.3: опрос таблицы раз в 15 с (пауза при скрытой вкладке), `get_state` один раз на сессию (при смене статуса или
  `startedat` — снова), `get_facts` с `sincerev` раз в 60 с, не больше четырёх запросов одновременно; карточка читает факты сразу и
  потом раз в 30 с (3 с при `l1_ports`).

**Интерфейс (§5).** Раскладка как у `lab.php` (`embedded`, поверх всего); таблица с закреплёнными первым столбцом и шапкой, поиск, сортировка
по имени и по состоянию в лабе (сначала ошибка сессии, затем ошибки в фактах, предупреждения, остальные запущенные, запуск, остановка,
остановленные, не начинал, недоступно), счётчики «работают / ошибка / не начинали» по каждой лабе, пометка `!` в шапке лабы без ответа менеджера.
Ячейка запущенной сессии: число `bad` и `warn` (цвет по худшему), `✓` без находок, серый `◌` при неизвестных или устаревших фактах
(и у сессии без `facts`), «Нет изменений с HH:MM» до первой смены `rev` и «Без изменений N мин» после. Карточка: шапка, «Открыть схему»,
находки слоёв L1 / L2 / L3 / маршрутизация (важные первыми), устройства (состояние, интерфейсы подняты / всего, IPv4), блок
«История попыток и проверок» с `data-region="history"` и скрытым `ul[data-region="historylist"]` под будущие записи, без запросов. Адрес
`#cm=&user=` открывает и закрывает карточку (кнопка «назад» браузера работает). Телефон 360 px: прокрутка внутри таблицы, карточка на весь
экран с кнопкой «←», цели касания не меньше 40 px.

**Проверки (§8).**

  студентов и не может выбрать чужую группу; ячейка чужой группы в лабе с раздельными группами — прочерк, в лабе без групп — обычная; преподаватель без своей группы в лабе с раздельными группами не видит никого; лаба без `observe` не

## 12. Сводка и вид одной лабы (0.28.0)

### 12.1. Решения владельца

- Вход не меняется: пункт «Лабы курса» в меню «Ещё» курса и кнопка на `view.php`.
- Общая таблица «студенты × лабы» больше не показывает живое состояние всех лаб сразу. Наверху страницы вкладки:
  **«Сводка»** и по вкладке на каждую лабу курса. По умолчанию открывается сводка.
- Сводка показывает **оценки**. Хранилище оценок — журнал оценок Moodle, своей копии плагин не заводит. В ячейке —
  **итоговая** оценка журнала (`finalgrade`): если преподаватель исправил её в журнале вручную, видна исправленная, с пометкой
  «Исправлена вручную в журнале оценок». Править оценки на странице нельзя; в шапке ссылка «Журнал оценок» (отчёт оценщика).
- Живое состояние (сессия, находки фактов, «без изменений N мин») — во вкладке лабы, только по этой лабе.

### 12.2. Данные

`mod_gns3lab_get_course_overview(courseid, groupid=0, cmid=0)`:
- `cmid` — только эта лаба (вкладка лабы); лаба не из доступных пользователю → `invalid_parameter_exception`. Менеджер
  спрашивают только о ней. `0` — все лабы (сводка).
- `showgrades` — у пользователя есть `moodle/grade:viewall` в курсе. Без него оценок в ответе нет (`gradetype: none`, `grade: null`).
- У лабы: `gradetype` (`none` / `value` / `scale`), `grademax`, `gradepass` (пусто, если проходная в журнале не задана) и
  `average` — средняя оценка тех студентов ответа, у кого она есть (у шкалы пусто). Всё уже отформатировано журналом.
- У ячейки: `grade` — `{text, ratio, passed, overridden, gradedat}` или `null`; `passed` — `yes` / `no` относительно проходной,
  пусто без проходной; скрытая оценка — только при `moodle/grade:viewhidden`. `checks` — сводка прогонов автопроверки:
  `{attempts, laststatus, lastoutcome, lastat}` или `null`; `attempts` — оценённые попытки.
- Источник оценок — `grade_item` и `grade_grade::fetch_users_grades()` (`classes/local/course_results.php`), прогонов —
  таблица `gns3lab_check_runs` одним запросом на лабу. Менеджер для этого не нужен, контракт с ним не меняется.
- История проверок в карточке — существующий `mod_gns3lab_get_checks(cmid, userid)` (observe и группы проверяет он сам).

### 12.3. Интерфейс

- Вкладки — ссылки `course.php?id=<курс>` и `course.php?id=<курс>&lab=<cmid>`; переключение без перезагрузки
  (`history.pushState`), кнопки «назад» и «вперёд» браузера работают, адрес можно открыть заново. Карточка, как и раньше,
  в `#cm=&user=`; при смене вкладки она закрывается.
- **Сводка.** Строки — студенты, столбцы — лабы в порядке курса и «Сдано». Ячейка: оценка (зелёная — не ниже проходной,
  красная — ниже, без цвета — проходной нет), `✎` у исправленной вручную, точка `●` у лабы, запущенной сейчас. Без оценки —
  как далеко продвинулся студент: «Не начинал», «Работает», «Идёт проверка», «Ошибка», «Нет оценки» (начинал, оценки нет;
  в лабе без оценивания — «Начал»). «Сдано» — `N / M`: из лаб с оценкой, где студента можно наблюдать, сколько с оценкой не ниже
  проходной (без проходной — просто с оценкой). Последняя строка — по лабе: средняя и «Сдали N из M» («Оценено N из M» без
  проходной), у лабы без оценивания — «Без оценки». Заголовок лабы открывает её вкладку. Сводка фактов не читает.
- **Вкладка лабы.** Строка — студент, столбцы: «Сессия» (состояние и время, цветная полоса по худшему), «Схема» (число
  находок `bad` / `warn`, `✓`, серый `◌`, «без изменений N мин»), «Проверки» («Попыток: N», «Идёт проверка», время
  последней), «Оценка» (если оценки видны и лаба оценивается). Сортировка по умолчанию — «что требует внимания» (как прежняя
  сортировка по состоянию), ещё по имени и по оценке. Над таблицей — счётчики лабы: работают / ошибка / не начинали,
  «Сдали» или «Оценено», средняя. Карточку открывает щелчок по строке или кнопка имени.
- **Карточка.** Добавлена строка «Оценка в журнале: X из Y · Исправлена вручную · проходная: Z» (или «пока нет») и настоящая
  история проверок: по строке на прогон, новые сверху — время, «оценка N» / «идёт» / «не удалась» / «не завершена», счётчики
  находок. Перечитывается, когда в таблице меняется последняя проверка студента. В лабе без автопроверок — «Автопроверки
  в этой лабе выключены». Карточку можно открыть и из сводки: она сама читает факты запущенной лабы.
- Телефон: вкладки прокручиваются вбок, таблицы — внутри своего блока, карточка на весь экран.

## 13. Оценки автопроверок, плотная таблица, сортировка (0.33.0)

### 13.1. Решения владельца

- Студентов много: строки таблиц (сводка и вкладка лабы) — минимальной высоты, чтобы на экран помещалось как можно больше.
- Сортируется каждый столбец.
- Оценка видна всегда, когда она есть. Почему её не было: таблица брала оценку только из журнала, а у новых элементов тип
  оценки по умолчанию «Нет» (`docs/autochecks.md` §4) — журнал пуст, хотя автопроверка оценку поставила.
- Метрика «кто справился лучше»: при равной оценке выше тот, кто получил её за меньшее число оценённых автопроверок,
  затем — кто раньше. Пятёрка с первой проверки выше пятёрки со второй, то же для четвёрок и троек.

### 13.2. Данные

`mod_gns3lab_get_course_overview`:
- у лабы `checks` — автопроверки включены (`checksenabled`);
- в сводке прогонов ячейки (`checks`) — `mark` (отметка последнего оценённого прогона — та, что уходит в журнал; `-1` без
  него), `topmark` и `failmark` этого прогона, `markedat`. Отметка есть при любом типе оценки элемента. Как и оценки журнала,
  отметки отдаются только при `moodle/grade:viewall`: без права `mark: -1`. Число попыток и состояние прогона видны, как и раньше.

### 13.3. Интерфейс

- **Оценка ячейки** (`resultOf` в `course.js`): исправленная вручную оценка журнала (с `✎`); иначе отметка автопроверки
  («5»); без отметки — оценка журнала как есть. Сдано: не ниже проходной журнала, а без проходной — выше «неуда» автопроверки
  (`failmark`). Лаба показывает результаты, если у неё есть оценка в журнале или включены автопроверки; иначе «Без оценки».
- В сводке рядом с оценкой — `×N`, число оценённых автопроверок (подсказка «Оценённых автопроверок: N»).
- **Сводка**, столбцы: «Студент», по лабе (у заголовка — ссылка на вкладку и стрелка `↕` сортировки), «Сдано» (`N / M`),
  «Средняя» (средняя показанных оценок), «Проверок» (сумма оценённых автопроверок по лабам с результатом; столбец есть, если хоть
  в одной лабе включены автопроверки). Внизу по лабе — средняя показанных оценок и «Сдали N из M».
- **Вкладка лабы**: сортируются все столбцы — «Сессия» (что требует внимания), «Схема» (больше ошибок, затем предупреждений —
  выше), «Проверки» (идёт сейчас, затем меньше попыток), «Оценка».
- **Порядок.** Первый щелчок — «лучшие сверху»: оценка по убыванию, при равной — меньше автопроверок, затем раньше; «Сдано» —
  больше сданных, затем выше средняя доля и меньше автопроверок; «Средняя» — выше, затем меньше автопроверок; «Проверок» —
  меньше сверху. Второй щелчок переворачивает порядок. Студенты без значения в столбце (нет оценки, не запускал) всегда внизу,
  между собой — по имени.
- **Плотность.** Строка ~25 px вместо ~50: ячейки без вертикальных полей, кнопки ячеек и имени без минимальной высоты 44 px,
  аватар 18 px, время сессии и последней проверки — в той же строке через «·». На телефоне (≤ 720 px) кнопки остаются 40 px
  под палец.
- Карточка: строка «Оценка автопроверки: N · Оценённых автопроверок: K» над строкой журнала.
- 0.33.1: строки обеих таблиц чередуются по фону (каждая вторая чуть темнее), строка под указателем подсвечивается целиком —
  и при наведении на имя, и на любую ячейку; строка открытой карточки отмечена сильнее. Цвета — смесью переменных темы,
  тёмная тема не ломается. Проверка — `check_course.js` («every other row is shaded», «the pointer over a name lights the whole row»).
- 0.33.2: в истории проверок карточки завершённая попытка — кнопка: щелчок раскрывает под ней отчёт прогона, повторный —
  сворачивает; открыта одна попытка за раз. Отчёт читается существующим `mod_gns3lab_get_check_run(cmid, runid, userid)`
  (наблюдателю подробности видны всегда, `checks::details_visible`) один раз и кэшируется на странице: завершённый прогон не
  меняется. Находки — как в панели студента (`checkreport.groupFindings`): сначала засчитанные критичные, значительные, мелкие,
  у причины — её «следствия», в конце прощённые; без находок — «Ошибок не найдено.»; правила, которые не удалось проверить, —
  списком «Проверено не всё». Идущая и неудавшаяся попытки не раскрываются. Сервер и контракт не менялись.
  Проверка — `check_course.js` (отчёт с критичной и следствием, прощённая, прогон без находок, повторное открытие без запроса).

### 13.5. Проверка на стенде (владелец)

1. Лаба с типом оценки «Нет» и автопроверками: два студента сдают на 5 — один с первой проверки, другой со второй.
2. «Лабы курса» → сводка: в ячейках «5 ×1» и «5 ×2»; стрелка `↕` у заголовка лабы ставит первого выше второго, повторный

3. Исправьте оценку вручную в журнале у лабы с оценкой: видна оценка журнала с `✎`.
4. На экране ноутбука помещается заметно больше строк; на телефоне ячейки остаются удобными для пальца.
5. Вкладка лабы: каждый заголовок сортирует таблицу.
6. Ассистент без `moodle/grade:viewall`: оценок и отметок нет, состояния и число попыток видны.
