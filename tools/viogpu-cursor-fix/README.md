# viogpudo с исправленным курсором (Windows-гость с консолью VNC)

Сборка видеодрайвера VirtIO GPU для Windows из [PR #1715 virtio-win](https://github.com/virtio-win/kvm-guest-drivers-windows/pull/1715)
с тестовой подписью. Временная мера, пока PR не принят и не вышел в обычном virtio-win.

## Зачем

В выпущенном viogpudo аппаратный курсор отстаёт на одну форму. Драйвер загружает картинку курсора по основной очереди
команд и, не дожидаясь, отправляет команду показа по очереди курсора. QEMU часто выполняет показ раньше загрузки и берёт
прежнюю картинку. Поэтому стрелка «изменить размер» остаётся после ухода с края окна, а точка щелчка смещается, и кнопки
будто не нажимаются. PR #1715 ждёт окончания загрузки (не дольше 100 мс) и, кроме того, переводит монохромные курсоры
(I-образный над текстом и другие) в цветные, чтобы Windows не рисовала их сама.

Что меняет наша сборка, кроме PR: установочный файл драйвера включает аппаратный курсор (`HWCursor = 1`). В выпущенном
драйвере по умолчанию 0, и правка курсора без него не работает.

## Сборка

Workflow `.github/workflows/viogpu-cursor-fix.yml` на сборщике GitHub `windows-2022` (Visual Studio 2022 и WDK)
запускает `build.ps1`:

1. берёт закреплённый коммит PR #1715 (`f01037a8…`, состояние на 24.11.2026);
2. ставит в INF `HWCursor = 1`;
3. собирает `viogpu.sln`, конфигурация `Win10 Release`, x64; пакет ставится на Windows 10 и 11;
4. подписывает `viogpudo.sys` и `viogpudo.cat` новым самоподписанным сертификатом и проверяет, что каталог
   покрывает драйвер.

Запуск: GitHub → Actions → «viogpudo cursor fix» → Run workflow. Можно указать другой коммит, например когда в PR
появятся новые правки. Сборка запускается и сама, когда меняются этот каталог или workflow. Результат — артефакт
`viogpudo-win10-x64-test-signed`:

```
viogpudo/                       драйвер: viogpudo.sys, viogpudo.inf, viogpudo.cat, viogpudo.pdb
tools/                          viogpusc.exe и viogpuap.exe — служба смены разрешения (если собрались)
gns3lab-viogpudo-test.cer       сертификат этой сборки
BUILD.txt                       коммит, версия драйвера, отпечаток сертификата, SHA-256 файлов
```

У каждой сборки свой сертификат: после пересборки гостю нужен новый `.cer`.

## Установка в образ

Перед установкой сделайте копию образа: ошибка видеодрайвера может дать синий экран при загрузке.

PowerShell или командная строка от администратора, в каталоге распакованного артефакта:

```bat
:: 1. Тестовый режим подписи драйверов (у нод GNS3 обычный BIOS, Secure Boot ему не мешает)
bcdedit /set testsigning on

:: 2. Доверие сертификату сборки
certutil -addstore -f Root gns3lab-viogpudo-test.cer
certutil -addstore -f TrustedPublisher gns3lab-viogpudo-test.cer

:: 3. Убрать из хранилища драйверов прежний viogpudo: подписанный Red Hat Windows считает лучше тестового
pnputil /enum-drivers
::    найти «Исходное имя: viogpudo.inf», запомнить «Опубликованное имя» (oemNN.inf), затем:
pnputil /delete-driver oemNN.inf /uninstall /force

:: 4. Поставить новый
pnputil /add-driver viogpudo\viogpudo.inf /install
```

Перезагрузите Windows. В «Диспетчере устройств» → Red Hat VirtIO GPU DOD controller → «Драйвер» дата и версия должны
совпасть с `DriverVer` из `BUILD.txt`. В правом нижнем углу рабочего стола появится надпись «Тестовый режим»: так и
должно быть.

Если после шага 3 Windows поставила «Базовый видеоадаптер (Майкрософт)» — это нормально, шаг 4 вернёт VirtIO.

## Что проверить

1. Указатель двигается без задержки.
2. Форма меняется сразу: над краем окна — двусторонняя стрелка, сошли с края — обычная стрелка, над текстом —
   I-образный курсор. Второго указателя рядом нет.
3. Кнопки нажимаются с первого раза, точка щелчка совпадает с кончиком стрелки.
4. Если курсор так и остался вязким — проверьте `HWCursor = 1` в разделе реестра драйвера («Свойства» адаптера →
   «Сведения» → «Ключ драйвера»).

## Возврат на официальный драйвер

Когда PR #1715 выйдет в virtio-win: удалить наш пакет (`pnputil /enum-drivers`, найти наш `viogpudo.inf` по дате,
`pnputil /delete-driver oemNN.inf /uninstall /force`), поставить драйвер с ISO virtio-win, выключить тестовый режим
`bcdedit /set testsigning off` и убрать сертификат (`certutil -delstore Root "GNS3 lab viogpudo test signing"`, то же для
`TrustedPublisher`). В официальном драйвере `HWCursor` снова будет 0 — включите его в реестре, как раньше.
